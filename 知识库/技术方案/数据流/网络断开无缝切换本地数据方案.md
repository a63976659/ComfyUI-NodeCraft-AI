# 网络断开无缝切换本地数据方案

## 来源

参考工具/项目：ComfyUI-Ranking（本地社区榜单插件）
验证状态：NodeCraft AI 同类生产验证（七大列表界面 + 顶部广告横幅全量落地）

## 适用场景

前端侧边栏/面板类插件，界面数据依赖远程接口（榜单、列表、配置），需要满足：

- 断网或云端暂时连不上时，界面不显示"加载失败"，直接展示上次看过的内容
- 重启 ComfyUI 后离线依然可用
- 网络恢复后自动静默刷新，用户无感知
- 打开界面、切换子页面不等待网络，秒级渲染

## 核心思路

**缓存立即渲染 + 网络退到后台**。任何数据请求都不阻塞首屏：先按"内存缓存 → localStorage 缓存 → 占位降级"三级取数并立即渲染，网络请求一律退到后台静默同步，成功则无感刷新、失败则保留已展示内容。整体表现为四种状态：

| 状态 | 行为 |
|------|------|
| 缓存有效 | 立即渲染缓存，后台静默刷新 |
| 缓存过期 + 有网 | 立即渲染过期缓存，后台静默刷新 |
| 缓存过期 + 断网 | 立即渲染过期缓存，轻提示"网络不可用，展示缓存" |
| 无缓存 + 断网 | 报错并给重试入口（离线回退的前提是本地曾存下缓存，这是设计预期而非 bug） |

## 实现步骤

### 1. 缓存读取必须"非破坏性"

提供两种读缓存语义，离线回退路径只允许用非破坏性版本：

```js
// ❌ 破坏性读取：过期即删除 —— 离线回退数据会被自己删掉
function getCache(key) {
    const raw = localStorage.getItem(key);
    if (!raw) return null;
    const { value, expires } = JSON.parse(raw);
    if (Date.now() > expires) {
        localStorage.removeItem(key); // 过期数据被销毁
        return null;
    }
    return value;
}

// ✅ 非破坏性读取：过期数据可读且不删除，由调用方决定是否使用
function getCacheWithMeta(key) {
    try {
        const raw = localStorage.getItem(key);
        if (!raw) return { value: null, found: false, expired: false };
        const { value, expires } = JSON.parse(raw);
        return { value, found: true, expired: Date.now() > expires };
    } catch {
        localStorage.removeItem(key); // 仅数据损坏时才清除
        return { value: null, found: false, expired: false };
    }
}
```

### 2. 列表首屏四态读取

```js
async function loadList(forceNetwork = false) {
    const { value, found, expired } = getCacheWithMeta(cacheKey);

    // 命中即渲染（无论是否过期），不等待任何网络结果
    if (found && !forceNetwork) {
        renderList(value);
        if (!expired) return;              // 缓存新鲜：静默刷新可选
        syncInBackground();                // 缓存过期：后台刷新
        return;
    }

    // 无缓存：只能等网络，但必须捕获失败并给出重试入口
    try {
        const data = await fetchFromNetwork();
        setCache(cacheKey, data, ttl);
        renderList(data);
    } catch (err) {
        showErrorWithRetry();              // 第四态：报错 + 重试按钮
    }
}

async function syncInBackground() {
    try {
        const data = await fetchFromNetwork();
        setCache(cacheKey, data, ttl);
        if (dataChanged(data)) renderList(data);  // 有变化才重绘，避免闪烁
    } catch {
        // 静默失败：保留当前展示内容，不打断用户
    }
}
```

### 3. 网络层兜底：离线捷径 + 重试耗尽后回退过期缓存

在统一 fetch 封装中加入两道保险：

```js
// 保险一：明确断网时不发起请求，直接回退过期缓存
if (!navigator.onLine && method === "GET") {
    const { value, found } = getCacheWithMeta(`api_${endpoint}`);
    if (found) return value;               // 过期也返回
    throw new Error("网络已断开，且无本地缓存");
}

// 保险二：有网但请求全部失败（重试耗尽）后，先回退过期缓存再抛错
catch (finalError) {
    const { value, found } = getCacheWithMeta(`api_${endpoint}`);
    if (found) return value;
    throw finalError;
}
```

### 4. 辅助数据（分类、配置）三级取数 + 空占位，绝不阻塞

子页面切换常依赖"先拉分类/配置再渲染列表"，这是最常见的阻塞点。改为三级取数，命中与否都立即渲染：

```js
function loadCategoriesAndReload() {
    let list = null;
    // 1. 内存缓存（同一会话内重复进入/切换）
    if (memoryCache && memoryCache.type === currentType) list = memoryCache.list;
    // 2. localStorage 缓存（重启后离线可用）
    if (!list) {
        const stored = loadStoredCategories(currentType);
        if (stored) { memoryCache = { type: currentType, list: stored }; list = stored; }
    }
    // 3. 无任何缓存：空列表占位，立即渲染
    if (!list) { memoryCache = { type: currentType, list: [] }; list = []; }

    renderCategoryBar(list);   // 空列表也要能安全渲染（保留固定的"全部"项）
    loadList(1);               // 列表加载不被分类请求阻塞

    // 网络请求一律退到后台，成功后自动补全分类栏
    if (!syncing) { syncing = true; syncCategoriesInBackground(); }
}
```

### 5. 后台同步的竞态防护（模块切换场景）

用户快速切换子模块时，正在飞的请求返回时"当前模块"可能已变。处理规则：

```js
let syncing = false;

async function syncCategoriesInBackground() {
    const typeAtSync = currentType;   // 记录发起时的模块
    try {
        const list = await fetchCategories(typeAtSync);
        if (typeAtSync !== currentType) {
            // 期间已切换模块：结果转存到对应模块缓存，再重新同步当前模块
            saveStoredCategories(typeAtSync, list);
            syncCategoriesInBackground();   // 递归接力
            return;                         // ⚠️ 此处不能复位 syncing
        }
        saveStoredCategories(typeAtSync, list);
        renderCategoryBar(list);
    } catch { /* 保留旧缓存 */ }
    finally {
        // 只有"当前模块"分支才释放标记；递归链由最终一环统一释放
        if (typeAtSync === currentType) syncing = false;
    }
}
```

## 关键代码

缓存写入带 TTL，持久化到 localStorage（重启 ComfyUI 后仍有效）：

```js
function setCache(key, value, ttl) {
    try {
        localStorage.setItem(key, JSON.stringify({
            value,
            expires: Date.now() + ttl
        }));
    } catch (e) {
        // localStorage 容量超限时静默降级：清理本模块旧缓存后重试一次，仍失败则放弃
        console.warn("缓存写入失败:", e);
    }
}
```

写操作（点赞、发布等）成功后**精准失效**关联缓存，而非全量清空：

```js
// 按映射表只删除受影响的键，避免离线回退数据被误伤
function invalidateRelatedCache(action, targetId) {
    for (const key of INVALIDATE_MAP[action] || []) {
        localStorage.removeItem(key);
    }
}
```

## ComfyUI 适配要点

1. **存储选型**：侧边栏类界面用 `localStorage`（跨重启保留）；仅会话内有效的降级副本用 `sessionStorage` 作补充源。ComfyUI 页面刷新不丢 localStorage。
2. **缓存键命名**：按模块加前缀并带维度参数，如 `ListCache_plugins_hot_1`、`CategoriesCache_image`，便于精准失效与清理。
3. **渲染安全**：占位空数据必须能安全渲染——分类栏恒定保留"全部"项，列表用 `(data || [])` 防御。
4. **重绘防闪烁**：后台同步成功后先对比数据是否变化（长度 + 抽样字段），有变化才重绘。
5. **生命周期**：组件销毁时清理未完成的后台同步回调引用，避免向已卸载的 DOM 渲染。
6. **图片资源**：缓存只覆盖数据（JSON），图片可另走本地缓存代理，离线时同样能显示。

## 注意事项（踩坑清单）

1. **破坏性读缓存是离线回退的头号杀手**：过期即删除的读取函数一旦用在首屏或失败回退路径，离线数据会被自己销毁。回退路径必须统一走非破坏性读取。
2. **`navigator.onLine` 检测不出"有网但连不通"**：WiFi 已连、代理链路故障时 `navigator.onLine === true`，离线捷径不会生效，请求会真实发出并撞上超时+重试。因此必须叠加"重试耗尽后回退过期缓存"的保险二，且**渲染绝不能等待这个请求**。
3. **超时 × 重试预算决定最坏等待时长**：例如 30 秒超时 × 3 次尝试 ≈ 92 秒。任何 `await` 在首屏路径上的请求都可能让界面卡 1 分半钟——这是"切换子界面很慢"类问题的典型根因。
4. **辅助请求阻塞首屏是隐蔽陷阱**：列表本身缓存优先了，但"先 await 分类再加载列表"这类前置依赖会重新引入阻塞。排查加载慢时要看整条依赖链，不只看列表请求。
5. **同步标记（防重复请求）的释放位置**：递归/接力式后台同步中，中途 `return` 的分支绝不能提前复位标记，否则窗口期内会重复发请求；应由递归链最终一环的 `finally` 统一释放。
6. **localStorage 写入会抛异常**：容量上限、隐私模式都可能失败。`JSON.parse` 读缓存也必须包 try-catch，损坏数据清除后按无缓存处理，不能让异常打断渲染。
7. **禁止全量清缓存**：写操作后全量清空会让离线回退数据整体失效；必须按映射表精准失效受影响的键。
8. **第四态要如实报错**：无缓存 + 断网时不要假装成功或永久转圈，明确报错并给重试按钮——用户联网后重试即可自愈，这也是让缓存"先存下来"的唯一路径。
9. **本地媒体代理会饿死浏览器连接池**：页面通过本机代理接口转发图片/视频时，代理对不可达源站"挂满超时才失败"，而浏览器对同一 localhost 源只有 6 条 HTTP/1.1 并发连接——批量未缓存媒体请求会占满通道，连带卡住动态 import 的界面模块和本地 API 调用，前端缓存做得再好界面照样打不开。解法是在本地代理加"云端可达性熔断器"：连续 N 次网络层失败即短路（图片毫秒返回占位图、视频返回 503），冷却到期自动半开放行，收到任何 HTTP 应答即复位；同时把单次下载超时收窄（总超时 + connect 超时双限）。
10. **中文 Windows 控制台（GBK）打不出非 BMP 字符**：print 日志里的 astral 平面 emoji（🚦 等）甚至 ⚠（U+26A0）都会在 GBK stdout 抛 UnicodeEncodeError；若该 print 位于异常处理路径，会二次抛异常破坏错误响应。异常/失败路径的日志标记只用 GBK 可编码的中文字符 + ASCII 符号（如 `[!]`），emoji 仅留在代码注释里（源码是 UTF-8 文件，不经过控制台编码）。
