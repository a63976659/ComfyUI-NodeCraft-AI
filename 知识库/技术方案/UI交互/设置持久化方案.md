# 设置持久化方案

## 来源
参考工具/项目：ComfyUI-Chinese-Translation（https://github.com/AIGODLIKE/AIGODLIKE-ComfyUI-Translation）
定位：config.json 为唯一真实源的设置持久化体系，解决"重启后设置丢失/回退默认值"与"设置面板显示值与实际配置脱节"两大问题（NodeCraft AI 生产验证）

## 适用场景
- 插件设置需要在 ComfyUI 重启后完整恢复（"下次启动直接读取最后一次保存的选择"）
- 设置同时涉及后端行为（如翻译开关、语言）与前端显示（设置面板下拉框）
- 需要兼容新旧版 ComfyUI 的设置存储机制（localStorage / 服务器端 userdata）
- 设置可能被外部修改（手动编辑 config.json、多标签页/多客户端）

## 核心思路
**config.json 是唯一真实源**：后端 get_config 每次从磁盘重读（不信任内存缓存），set_config 切换即保存并同步内存；前端用 `currentConfig` 内存镜像驱动行为，并通过三重守卫（applyingConfig / isSettingsRegistered / isSettingsDialogOpen）防止 ComfyUI 设置商店的程序性写入（hydration 等）把旧值回写磁盘；设置对话框显示值通过"打开时刷新 + 注册后收敛轮询"与 config.json 保持一致。

## 实现步骤

### 1. 后端：磁盘重读型 get_config + 双写型 set_config
```python
def load_config():
    config_path = CUR_PATH.joinpath("config.json")
    default_config = {"enabled": True, "style": "gradient"}  # 全字段默认值
    if config_path.exists():
        try:
            default_config.update(try_get_json(config_path))
        except Exception:
            pass  # ⚠️ 静默回退默认值——这正是内存分歧的根源，见注意事项 1
    return default_config

GLOBAL_CONFIG = load_config()  # 启动时加载一次（可能已陈旧，故 get_config 必须重读）

@server.PromptServer.instance.routes.get("/xxx/get_config")
async def get_config(request):
    # ✅ 每次从磁盘重新读取，确保前端始终拿到最后一次保存的配置
    global GLOBAL_CONFIG
    GLOBAL_CONFIG = load_config()
    return web.Response(status=200, body=json.dumps(GLOBAL_CONFIG),
                        headers={"Content-Type": "application/json"})

@server.PromptServer.instance.routes.post("/xxx/set_config")
async def set_config(request):
    post = await request.post()
    config_data = { ... }  # 解析并组装全部字段
    with open(config_path, 'w', encoding='utf-8') as f:
        json.dump(config_data, f, indent=2, ensure_ascii=False)  # 先写盘
    global GLOBAL_CONFIG
    GLOBAL_CONFIG = config_data  # 再同步内存，读写两条路径均与磁盘一致
    return web.Response(status=200, body=json.dumps({"success": True}))
```

### 2. 前端：onChange 三重守卫（切换即保存，且防程序性回写）
```javascript
const SETTING_ID_STYLE = "分类.设置名";
let applyingConfig = false;        // 程序性同步防护标志
let isSettingsRegistered = false;  // 注册完成标志

// 设置对话框选择器（新旧版兼容）
const DIALOG_SELECTOR = '#comfy-settings-dialog, .p-dialog, [role="dialog"], [class*="z-1700"]';
const isSettingsDialogOpen = () => !!document.querySelector(DIALOG_SELECTOR);

app.ui.settings.addSetting({
  id: SETTING_ID_STYLE,
  type: "combo",
  options: STYLE_OPTIONS,
  defaultValue: styleLabelOf(currentConfig.style),
  onChange: async (newVal) => {
    if (applyingConfig) return;        // 守卫1：拦截程序性同步回写
    if (!isSettingsRegistered) return; // 守卫2：拦截注册期的初始回调
    if (!isSettingsDialogOpen()) return; // 守卫3：拦截 hydration 等非用户操作
    const key = parseStyleKey(newVal);
    if (key !== currentConfig.style) {
      await saveConfig(key);    // POST set_config，切换即保存
      renderToggle(app);        // 可即时重绘的项无需刷新页面
    }
  }
});
isSettingsRegistered = true;
```

### 3. 前端：config.json → 设置商店的显示同步
```javascript
/** 将当前配置回写到 ComfyUI Settings 商店（applyingConfig 包裹防回写环） */
function syncSettingsFromConfig(app) {
  const setter = app.ui.settings.setSettingValue?.bind(app.ui.settings);
  if (!setter) return;  // 旧版兼容
  applyingConfig = true;
  try {
    setter(SETTING_ID_STYLE, styleLabelOf(currentConfig.style));
    // ...其余设置项
  } finally {
    applyingConfig = false;
  }
}

/** 设置对话框每次打开时，先拉最新配置再同步显示值（dataset 去重） */
function syncSettingsDialogIfOpen() {
  const dialogEl = document.querySelector(DIALOG_SELECTOR);
  if (!dialogEl || dialogEl.dataset.tlSynced) return;
  dialogEl.dataset.tlSynced = "1";
  (async () => {
    await refreshCurrentConfig();  // GET get_config（后端从磁盘重读）
    syncSettingsFromConfig(app);
  })();
}

/** 商店收敛：注册后 10 秒内轮询，纠正晚到 hydration 写入的旧值 */
function startStoreConvergence(app) {
  const getter = app.ui.settings.getSettingValue?.bind(app.ui.settings);
  if (!getter) return;
  let checks = 0;
  const timer = setInterval(() => {
    checks++;
    try {
      const diverged = getter(SETTING_ID_STYLE) !== styleLabelOf(currentConfig.style);
      if (diverged && !isSettingsDialogOpen()) syncSettingsFromConfig(app);
    } catch (e) { /* 旧版兼容：静默 */ }
    if (checks >= 20) clearInterval(timer);
  }, 500);
}
// MutationObserver 监听 document.body 触发 syncSettingsDialogIfOpen
```

## ComfyUI 适配要点

1. **设置存储已换代**：旧版 ComfyUI 设置存 `localStorage["Comfy.Settings"]`（纯客户端，重启服务不丢）；新版改为**服务器端 userdata**（所有标签页/客户端共享）。依赖 localStorage 读取旧版可行，但对新版无效，应以 config.json 为准
2. **hydration 时机不可控**：新版页面加载时会把 userdata 旧值应用到设置商店，可能晚于插件的 `addSetting()` 注册，且会触发 onChange——这是"重启后设置被旧值覆盖"的直接推手，必须用对话框守卫拦截
3. **对话框 DOM 兼容**：旧版为 `#comfy-settings-dialog`，新版为 PrimeVue 的 `.p-dialog` / `[role="dialog"]`，选择器需同时覆盖
4. **setSettingValue 兼容**：旧版可能不存在，用可选链 `?.` + try/catch 包裹，同步失败不影响 config.json 实际生效
5. **即时 vs 重载**：纯 UI 变化（CSS/DOM 重绘）可即时生效；涉及后端数据编译的设置（语言、翻译范围）保存后需 `location.reload()`

## 注意事项（易踩坑点）

1. **⚠️ 内存与磁盘分歧（最隐蔽）**：`get_config` 若只返回启动时加载的内存 `GLOBAL_CONFIG`，一旦启动时 `load_config()` 读取失败（编码异常/文件锁定）静默回退默认值，内存将永久停留在默认值，前端每次加载都拿到陈旧配置——表现为"重启后设置变回默认"。修复：**get_config 每次从磁盘重读**
2. **⚠️ onChange 不只用户会触发**：`addSetting()` 注册初期、`setSettingValue()` 程序性写入、新版 userdata hydration 都会触发 onChange。无守卫时这些回调会把旧值 POST 回 set_config，**覆盖用户刚保存的 config.json**。三重守卫缺一不可
3. **⚠️ 对话框显示值是快照**：新版设置对话框显示的是页面加载时的商店值，config.json 被外部修改后打开对话框会显示陈旧值——每次打开对话框都要先拉最新配置再回写商店
4. **晚到的 hydration**：注册时同步一次商店不够，hydration 可能在之后才写入旧值；需要短时收敛轮询（仅对话框关闭时纠正，避免干扰用户操作）
5. **保存时序**：必须 `await saveConfig()` 完成后再 `location.reload()`，否则刷新打断保存请求
6. **默认值来源**：`defaultValue` 应从已加载的配置取，而非硬编码，否则首屏显示与实际行为不一致
7. **JSON 编码**：中文 Windows 下 config.json 可能被其他工具写成 gbk，读取需 utf-8/gbk 双编码 fallback；写盘统一 utf-8 + `ensure_ascii=False`
8. **全字段回写**：set_config 应组装**全部**字段后整体写盘（而非增量 patch），否则未传字段会在重写时丢失；前端 saveConfig 同理要把未修改字段按当前值一并提交
