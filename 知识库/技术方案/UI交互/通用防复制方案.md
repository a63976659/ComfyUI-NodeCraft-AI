# 通用防复制方案

## 来源
参考工具/项目：NodeCraft AI 生产验证（三层防护思路来源于成熟项目的图片保护实践，已在功能可视化显示框等场景落地验证）
定位：为任意 UI 容器提供防误触右键菜单、防文本选中复制、防元素拖拽的通用能力，按容器交互属性分级选用，不破坏既有交互

## 适用场景
- 展示型区域需要防复制防右键（图片预览、可视化画布、只读面板、HUD 覆盖层）
- 拖拽/滚动操作中鼠标滑过悬浮弹窗（tooltip）意外触发文本选中与复制
- 容器本身承担鼠标交互（画布旋转/缩放/平移、可滚动区、自定义拖拽），不能用 `pointer-events: none`
- 需要在局部容器内防护，又不影响页面其他区域的正常选中复制

## 核心思路
三层冗余防护，各层职责分离，按容器类型分级选用：

1. **CSS 层（基础层，所有容器适用）**：`user-select: none`（含浏览器前缀）+ `-webkit-user-drag: none`，从样式上禁掉选中与原生拖拽
2. **JS 事件拦截层（兜底层，所有容器适用）**：容器上拦截 `contextmenu`/`dragstart`/`copy` 三个事件 `preventDefault()`，覆盖 CSS 管不到的场景（动态插入元素、表单控件、覆盖层）；输入框（`input, textarea`）走白名单放行
3. **悬浮窗源头治理（按需层，有 tooltip 的容器适用）**：tooltip 是误复制的常见源头（拖拽中弹窗出现在光标下被划选），用 `event.buttons` 判断拖拽中不弹窗，`pointerdown` 时收起残留弹窗

**关键决策：交互容器不用 `pointer-events: none`**。它是纯展示型元素（如 `<img>`）保护的核心手段，但承担鼠标交互的容器禁用后交互全废。交互容器用「CSS 禁选中 + JS 拦事件」替代，效果等价且保留交互。

**分级选用表：**

| 容器类型 | 典型例子 | 采用层级 |
|---|---|---|
| 纯展示型 | 图片、图标、只读徽标 | CSS 层即可；`pointer-events: none` 也可选 |
| 交互容器 | 3D 画布、可滚动列表、自定义拖拽区 | CSS 层 + JS 事件拦截层 |
| 带悬浮提示的交互容器 | 画布 + tooltip、图表 + 悬浮卡片 | 三层全上 |

## 实现步骤

### 1. CSS 层：容器禁选中禁拖拽
```css
/* 防复制保护（CSS 层）：禁止选中内容与原生拖拽。
   交互容器不用 pointer-events:none —— 会废掉容器自身交互，
   右键菜单/拖拽/复制由 JS 的事件拦截层兜底 */
.目标容器类名 {
    user-select: none;
    -webkit-user-select: none;
    -moz-user-select: none;
    -ms-user-select: none;
    -webkit-user-drag: none;
}
```

### 2. JS 事件拦截层：三事件拦截 + 输入框白名单
```javascript
// 输入框/文本域例外：保留其右键编辑菜单与复制能力；
// 若容器内无表单控件可去掉白名单直接拦截
const _防复制例外 = (e) => !!(e.target && e.target.closest && e.target.closest("input, textarea"));
container.addEventListener("contextmenu", (e) => { if (!_防复制例外(e)) e.preventDefault(); });
container.addEventListener("dragstart", (e) => e.preventDefault());
container.addEventListener("copy", (e) => { if (!_防复制例外(e)) e.preventDefault(); });
```

### 3. 悬浮窗源头治理（按需）：拖拽中不弹 tooltip
```javascript
// 拖拽中（按住鼠标操作画布/滚动/平移）不弹悬浮窗，避免弹窗
// 出现在光标下触发误复制；正常悬停（未按键）行为不变
function 显示tooltip(event, 内容) {
    if (event && event.buttons) {
        tooltip.classList.remove('visible');
        return;
    }
    // ... 正常显示 tooltip
}

// 拖拽起始瞬间收起残留悬浮窗：hover 类回调通常只在
// 「进出元素」时触发，已显示的 tooltip 不会自行消失
container.addEventListener("pointerdown", () => tooltip.classList.remove("visible"));
```

## ComfyUI 适配要点

1. **监听挂目标容器而非 `document`**：防护范围严格限定容器内，页面其他区域（聊天输入区、设置区）的正常选中复制不受影响
2. **CSS 前缀不可省**：ComfyUI 基于 Electron/Chromium，`-webkit-user-select` 与 `-webkit-user-drag` 是实际生效的前缀
3. **输入框白名单必须处理事件冒泡**：容器内搜索框等 `<input>` 的事件会冒泡到容器，`contextmenu`/`copy` 需用 `closest("input, textarea")` 放行，否则无法右键编辑和复制；CSS 的 `user-select: none` 不影响表单控件内部选中，无需额外处理
4. **第三方交互库可作天然第一层**：如 three.js OrbitControls 内部已对画布 `contextmenu` 调用 `preventDefault`，画布右键无需重复处理，JS 拦截层只需覆盖库管不到的覆盖层区域；接入其他库（图表、地图）时先查库自身的事件拦截，避免重复挂载
5. **全屏模式自动保持防护**：全屏通常是对同一容器元素调用 `requestFullscreen()`，监听与样式继续生效，无需为全屏单独加防护
6. **面板重建无泄漏**：监听挂在随面板一起重建/销毁的容器本元素上，旧面板销毁时监听一并回收，重建（如语言切换）不会累积监听；若挂在全局对象上则必须配对 `removeEventListener`

## 注意事项

1. **切勿对交互容器照搬 `pointer-events: none`**：该手段只适用于不承担交互的展示型元素；画布、可滚动区等禁用后功能全废
2. **`dragstart` 拦截不设白名单**：输入框拖拽选中文本属边缘场景，统一拦截实现更简单，实测无体验损失；如有富文本编辑需求需另行评估
3. **tooltip 治理选「拖拽抑制」而非「彻底取消」**：悬停提示是有用功能，只消灭拖拽误触场景，与 three.js editor、3d-force-graph 等成熟查看器做法一致
4. **`event.buttons` 判拖拽**：非零即按住鼠标状态，比自行维护 `mousedown/mouseup` 状态机更可靠，且能正确处理「容器外按下再移入」的边界
5. **防复制只是抬高门槛**：以上手段可挡住误触和普通复制，无法阻止开发者工具/截图等刻意获取，不要用于真正的机密内容保护
6. **已验证案例**：功能可视化显示框（`前端/可视化面板.js` + `前端/样式/可视化面板.css`）采用三层全上，实测右键无菜单、文字选不中、Ctrl+C 无效、画布旋转/缩放/平移与全屏均正常
