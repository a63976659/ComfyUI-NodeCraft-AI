# 节点缩放保持边缘宽度方案

## 来源
参考工具/项目：ComfyUI-prompt-formula（https://www.bilibili.com/video/BV1UBB2YhEpJ）
参考节点：提示词预设（`提示词预设`，实现文件 `网页资源/提示词预设.js` + `节点文件/提示词预设节点.py`）
定位：节点被用户自由缩放时，节点内嵌的 DOM 内容区（预览框等）始终保持固定的左右边缘留白，高度跟随节点尺寸自动重算，缩放后的尺寸可持久化到工作流

20260815 增补：ComfyUI-Artificial-Intelligence 插件「全部节点底部 10px 留白」实战中，验证了新版（Vue 版）前端布局机制与本方案四件套的适配边界，补充「新版前端布局机制」「冻结上限+防抖测量补齐」「双前端兼容策略」与完整踩坑记录（均已在本机 ComfyUI 0.33.1 前端源码中逐条核实）。

## 适用场景
- 节点内嵌 DOM 内容区（addDOMWidget 注入的预览框/自定义面板），需要随节点缩放自适应
- 要求内容区与节点左右边缘保持恒定边距（如左右各 8px），不随节点变宽而贴边或错位
- 节点尺寸需要持久化：用户调整的大小在保存/加载工作流后恢复
- onResize 可能不被触发的场景需要兜底感知尺寸变化
- 需要给节点统一加底部/四周留白（如最后一控件不贴底边框），且在新旧两版前端都要生效

## 前端版本分叉（先读这个）

ComfyUI 前端有两套布局机制，方案必须按版本选型：

| | 旧版画布前端（LiteGraph canvas 渲染） | 新版 Vue 前端（DOM 渲染，现为默认） |
|---|---|---|
| 布局入口 | `computeSize` + draw 时逐 widget 排版 | `_arrangeWidgets` 布局引擎（Vue 响应式异步重排） |
| 可见性判断 | `widget.type === "hidden"` 有效 | **只认 `widget.hidden`**，`type="hidden"` 不参与判断 |
| 剩余空间 | 不存在"吸收"概念 | 全部分给不限高的弹性组件（见下） |
| setSize | 有钳制路径可依赖 | **无钳制**，只赋值 + 触发 onResize |
| 命中检测 | canvas 命中 `last_y` | `last_y` 恒 null，由 Vue DOM 承接点击 |
| 本方案 | 四件套直接适用 | 四件套部分失效，须改用「冻结上限+防抖测量补齐」 |

判断当前前端：不要依赖 `app.vueNodesReady`（部分 build 不存在，如 0.33.1），推荐**双前端兼容写法**（见「双前端兼容策略」），或按「前端升级复核清单」实测确认。

## 核心思路
"CSS 相对宽度锁定边距 + onResize 高度重算 + 绘制帧兜底检测 + 序列化持久化"四件套（旧版画布前端）：
1. 内容区宽度用 `calc(100% - 2×边距)` 表达，边距天然恒定，无需 JS 干预宽度；
2. 拦截 `onResize`，用"节点高度 − 标题栏 − 其他组件 − 边距"重算内容区高度；
3. `onDrawForeground` 中比对缓存尺寸做兜底（部分缩放路径不触发 onResize）；
4. 重写 `serialize`/`configure` 把自定义尺寸写入/读出工作流数据。

新版 Vue 前端改为"冻结上限 + 防抖测量补齐"两件套（详见「新版前端实现方案」）：
1. 包装弹性组件的 `computeLayoutSize` 冻结高度上限，阻止留白被文本框吸收；
2. 布局稳定后测量可见组件实际底边，不足「底边 + 留白」才撑高节点，只增不减。

## 实现步骤（旧版画布前端四件套）

### 1. CSS：calc 锁定左右边距（边缘宽度的核心）
```css
.preset-content-preview {
    box-sizing: border-box;
    width: calc(100% - 16px);      /* 左右各留 8px 边距，缩放时恒定 */
    max-width: calc(100% - 16px);
    margin: 5px auto;              /* 水平居中，误差自动均摊到两侧 */
    padding: 8px;
    overflow: auto;
    min-height: 40px;
    white-space: pre-wrap;
    word-wrap: break-word;
}
```
要点：`box-sizing: border-box` 必须设置，否则 padding/border 会撑破 calc 宽度；用百分比相对表达式而非固定 px 宽度，是缩放时边距不变的关键。

### 2. 注入 DOM 内容区
```javascript
nodeType.prototype.onAdded = function() {
    原节点添加?.apply(this, arguments);

    // 恢复保存的尺寸（首次创建用默认值）
    this.setSize([this._nodeWidth || 300, this._nodeHeight || 200]);

    // 创建预览容器并经 addDOMWidget 注册（宽高自动跟随节点）
    this.预览容器 = $el("div", {
        className: "preset-content-preview preset-content-empty",
        textContent: "请选择预设文件..."
    });
    this.addDOMWidget("preset_preview", "preset_preview", this.预览容器, {
        getValue: () => "",     // 纯展示组件：空值实现，不参与序列化
        setValue: () => {}
    });
    // ...
};
```

### 3. 拦截 onResize：记录尺寸 + 重算内容区高度
```javascript
this.onResize = function(size) {
    原调整大小?.apply(this, arguments);

    // 记录当前尺寸（供序列化保存）
    this._nodeWidth = size[0];
    this._nodeHeight = size[1];

    this.自动调整预览框高度();
};

// 内容区高度 = 节点高度 − 固定占位（标题栏/其他组件/边距），设最小值兜底
this.自动调整预览框高度 = function() {
    if (!this.预览容器) return;
    const 标题高度 = 30;
    const 下拉框高度 = 30;
    const 边距 = 20;
    const 可用高度 = this.size[1] - 标题高度 - 下拉框高度 - 边距;
    this.预览容器.style.height = `${Math.max(40, 可用高度)}px`;
    this.setDirtyCanvas(true, true);
};

// 首次布局完成后初始化（DOM 就绪需要延迟）
setTimeout(() => this.自动调整预览框高度(), 100);
```

### 4. onDrawForeground 兜底：感知 onResize 漏触发的缩放
```javascript
const 原绘制前景 = nodeType.prototype.onDrawForeground;
nodeType.prototype.onDrawForeground = function(ctx) {
    原绘制前景?.apply(this, arguments);
    // 比对缓存尺寸，变化则重算（覆盖部分不触发 onResize 的缩放路径）
    if (this.预览容器 &&
        (this._lastWidth !== this.size[0] || this._lastHeight !== this.size[1])) {
        this._lastWidth = this.size[0];
        this._lastHeight = this.size[1];
        this.自动调整预览框高度();
    }
};
```

### 5. serialize/configure：尺寸持久化
```javascript
nodeType.prototype.serialize = function() {
    const 数据 = 原序列化 ? 原序列化.apply(this, arguments) : {};
    if (this._nodeWidth && this._nodeHeight) {
        数据._nodeWidth = this._nodeWidth;
        数据._nodeHeight = this._nodeHeight;
    }
    return 数据;
};

nodeType.prototype.configure = function(配置) {
    原配置?.apply(this, arguments);
    if (配置._nodeWidth && 配置._nodeHeight) {
        this._nodeWidth = 配置._nodeWidth;
        this._nodeHeight = 配置._nodeHeight;
    }
};
```
注意：ComfyUI 本身会序列化 `size`，此处额外存一份是为了在 `onAdded` 阶段（configure 之前）就能用 `_nodeWidth/_nodeHeight` 设初始尺寸；若只需加载恢复，直接读 `configure` 传入的 size 亦可。

## ComfyUI 适配要点

1. **边距交给 CSS 而非 JS**：`calc(100% - 2×边距)` + `box-sizing: border-box` 让宽度方向完全免维护，JS 只管高度
2. **addDOMWidget 的容器宽度跟随节点**：DOM widget 外层宽度由 ComfyUI 布局给定，内部用百分比即可获得正确参照
3. **高度重算用减法模型**：可用高度 = 节点高度 − Σ固定占位（标题栏约 30px、各组件约 30px/个、上下边距），并设 `Math.max(最小高度, ...)` 防止负值
4. **原型级钩子用链式包装**：`beforeRegisterNodeDef` 中重写 `onAdded/onResize/serialize/configure/onDrawForeground` 时都要先保存原方法并 `apply`，避免破坏其他扩展
5. **改完尺寸/内容必须 setDirtyCanvas(true, true)**，否则画布不重绘

## 新版（Vue 版）前端布局机制（0.33.1 源码实测）

机制结论来自新版前端运行时源码提取与浏览器实测，**前端升级后需按「前端升级复核清单」复核**。

### 可见性判断只看 `.hidden`

```js
isWidgetVisible(e) { return !(this.collapsed || e.hidden || e.advanced && !this.showAdvanced); }
getLayoutWidgets() { return this.widgets?.filter(e => !e.hidden) ?? []; }
```

**不检查 `widget.type === "hidden"`** —— 这是旧式隐藏法在新版失效、末尾组件被排出节点外不可点的总根源（踩坑 1）。

### 布局引擎 `_arrangeWidgets`：剩余空间全给弹性组件

```js
_arrangeWidgets(titleHeight) {
    let t = this.bodyHeight;                    // = size[1]，整个节点体高度都是布局区
    let n = this.widgets_start_y ?? (this.widgets_up ? 0 : titleHeight) + 2;
    let r = t - n, i = 0, a = [];
    let o = this.getLayoutWidgets();            // 只过滤 .hidden
    for (let e of o)
        if (e.computeSize)      { e.computedHeight = e.computeSize()[1] + 4; i += e.computedHeight; }
        else if (e.computeLayoutSize) { let {minHeight, maxHeight} = e.computeLayoutSize(this);
                                        a.push({minHeight, prefHeight: maxHeight, w: e}); }   // 弹性组件（STRING 文本框/DOM widget）
        else                    { e.computedHeight = NODE_WIDGET_HEIGHT + 4; i += e.computedHeight; }
    r -= i; this.freeWidgetSpace = r;
    let c = distributeSpace(Math.max(0, r), a.map(e => ({minSize: e.minHeight, maxSize: e.prefHeight})));
    for (let [idx, item] of a.entries()) item.w.computedHeight = c[idx];   // 剩余空间被弹性组件吸收
    let l = n;
    for (let e of o) { e.y = l; l += e.computedHeight ?? 0; }              // 布局写入 widget.y
    // vueNodesMode 下组件溢出时【不会】自动撑高节点
    if (!vueNodesMode && l > t) this.setSize([this.size[0], l]);
}
```

要点：

- STRING 文本框/DOM widget 的 `computeLayoutSize` 默认返回 `{minHeight: 50, maxHeight: undefined}`，**maxHeight 为 undefined = 不限高**，节点内任何多余高度都被它吸收（踩坑 3）；
- 布局结果写 `widget.y` 与 `widget.computedHeight`，**不写 `last_y`**；
- `minHeight` 固定（实测恒为 50 一类常量），不随文本内容增长（踩坑 4）；
- 节点级 `computeSize()` 对弹性组件只计 `minHeight`——即 computeSize 返回的是"自然最小高度"。

### 命中检测读 `last_y`，新版恒 null

新版布局不写 `last_y` → canvas 命中路径恒返回 null，真实点击由 Vue DOM 承接。因此"组件能否点击"取决于 **DOM 是否渲染在节点可视范围内**——组件被排到节点底边之外即不可点。

### 尺寸回调与重排时机

- `setSize(e) { this.size = e; this.onResize?.(this.size); }` —— **无钳制**，触发 `onResize`（踩坑 7：包装 computeSize 做"缩小下限钳制"在新版失效）；
- `bodyHeight` = `collapsed ? 0 : size[1]`。

| 操作 | 是否触发重排 |
|---|---|
| 节点创建 / 工作流 configure | ✅（Vue 响应式异步，实测 <100ms） |
| 组件值变化（如滑块拖动） | ✅ |
| 用户拖拽节点边角 resize | ✅ |
| 代码直接 `setSize(...)` | ❌ 不触发同步重排（异步，须防抖等待） |

## 新版前端实现方案：冻结上限 + 防抖测量补齐

适用目标：给节点加真实可见的边缘留白（底部/四周），或让内容区不被多余高度吸收。实战案例：ComfyUI-Artificial-Intelligence 全部 19 节点底部 10px（`web/节点底部边缘.js`，扩展名 `AI.NodeBottomPadding`）。

### 1. 冻结上限：阻止弹性组件吸收留白

包装弹性组件的 `computeLayoutSize`（幂等）：**首次布局不限高**（拿到自然分配高度），之后每次布局以上一次实际分配的 `computedHeight` 为 `maxHeight` 上限。多出的节点高度成为真实留白，文本框保持自然高度不被裁剪。

```javascript
function freezeWidgetCap(widget) {
    if (!widget || widget._已冻结) return;
    const 原计算 = widget.computeLayoutSize;
    if (typeof 原计算 !== "function") return;      // 固定高度组件无需处理
    widget.computeLayoutSize = function (node) {
        const r = 原计算.call(this, node) || {};
        // 幽灵组件（type==="hidden"）原实现返回全 0，必须原样放行，否则被解冻复活
        if (this.type === "hidden" || typeof this.computedHeight !== "number") return r;
        const 上限 = Math.max(r.minHeight || 0, this.computedHeight);
        const max = (r.maxHeight != null && r.maxHeight < 上限) ? r.maxHeight : 上限;
        return { ...r, maxHeight: max };
    };
    widget._已冻结 = true;
}
```

要点：
- 不能直接 `maxHeight = minHeight` 封顶——`minHeight` 恒为小常量，会把多行文本裁掉（踩坑 4）；
- 冻结必须幂等，且要在**每次测量前**对 `node.widgets` 全量补跑一遍，覆盖比本扩展晚注册的扩展追加的 widget（踩坑 6 的变体）。

### 2. 防抖测量补齐：布局稳定后才测量

```javascript
const 留白 = 10, 防抖毫秒 = 150, 重试上限 = 10;

function measureAndPad(node, attempt = 0) {
    if (!node || !node.widgets || node._补齐中) return;

    for (const w of node.widgets) freezeWidgetCap(w);   // 幂等冻结

    let 底边 = 0, 就绪 = true, 有可见组件 = false;
    for (const w of node.widgets) {
        if (w.hidden || w.type === "hidden") continue;
        if (typeof w.y !== "number" || typeof w.computedHeight !== "number") {
            就绪 = false;                                // 布局尚未完成
            break;
        }
        if (w.computedHeight <= 0) continue;             // 幽灵组件 [0,-4]
        有可见组件 = true;
        底边 = Math.max(底边, w.y + w.computedHeight);
    }
    if (!就绪) {
        if (attempt < 重试上限) setTimeout(() => measureAndPad(node, attempt + 1), 防抖毫秒);
        return;
    }
    if (!有可见组件 || 底边 <= 0) return;

    const 需要 = 底边 + 留白;
    if (node.size[1] < 需要) {
        node._补齐中 = true;
        node.setSize([node.size[0], 需要]);              // setSize 触发 onResize，用标记防递归
        node._补齐中 = false;
        schedulePad(node);                               // 布局异步重排，稳定后再复核一次
    }
}

function schedulePad(node) {
    if (!node) return;
    clearTimeout(node._补齐计时器);
    node._补齐计时器 = setTimeout(() => measureAndPad(node), 防抖毫秒);
}
```

要点：
- **只向上补齐、不向下收缩**，避免与用户手动 resize 打架；
- 测量必须防抖等布局稳定（150ms 起），`y/computedHeight` 未就绪延迟重试（上限 10 次），否则"测量→撑高→再测量"每轮 +留白 无限 runaway（踩坑 5）；
- 收敛性：补齐后重排中弹性组件被冻结上限卡住、底边不变，第二轮测量 `需要 == size[1]` 不再撑高。

### 3. 触发点全覆盖 + window 全局串联

```javascript
app.registerExtension({
    name: "扩展名",
    async beforeRegisterNodeDef(nodeType, nodeData, app) {
        if (!命中目标节点(nodeData.name)) return;

        // 手动拖拽缩放、程序化 setSize 均经 onResize 调度
        const 原onResize = nodeType.prototype.onResize;
        nodeType.prototype.onResize = function (size) {
            原onResize?.apply(this, arguments);
            if (!this._补齐中) schedulePad(this);
        };

        // 兜底：直接改 size 数组等不触发 onResize 的路径
        const 原绘制前景 = nodeType.prototype.onDrawForeground;
        nodeType.prototype.onDrawForeground = function (ctx) {
            原绘制前景?.apply(this, arguments);
            if (this.size &&
                (this._上次宽 !== this.size[0] || this._上次高 !== this.size[1])) {
                this._上次宽 = this.size[0];
                this._上次高 = this.size[1];
                schedulePad(this);
            }
        };

        // 旧工作流加载后补齐（补齐高度随原生 size 序列化自然持久化，无需包 serialize）
        const 原configure = nodeType.prototype.configure;
        nodeType.prototype.configure = function (info) {
            原configure?.apply(this, arguments);
            schedulePad(this);
        };
    },

    nodeCreated(node) {                       // 新建节点
        if (!命中目标节点(node.comfyClass)) return;
        schedulePad(node);
    },
});

// 扩展注册顺序不保证：暴露全局函数，供其他扩展在显隐/动态槽位变更后显式串联
window.__确保底部留白 = function (node) {
    if (node && 命中目标节点(node.comfyClass)) schedulePad(node);
};
```

行为边界（有意为之）：冻结后手动拉高节点 → 多出部分表现为留白；缩到内容溢出时补齐会把节点撑回底边+留白（顺带修复末尾组件被排出节点外不可点）；宽度一律不动，不覆盖用户手动拉宽的宽度。

## 双前端兼容策略

同一份代码同时支持新旧前端（实战验证可行）：

1. **保留 computeSize 原型包装**（高度 +留白）：旧版画布前端的新建初始尺寸、`expandToFitContent` 与其它插件的尺寸计算仍用它；新前端下仅影响初始尺寸计算，无副作用；
2. **叠加「冻结上限+防抖测量补齐」**：新版前端靠它产生真实留白；旧版前端下 `_arrangeWidgets` 同样是布局入口，机制一样生效；
3. **不要用 `app.vueNodesReady` 做版本门控**：部分 build 无此属性（0.33.1 实测），误判会导致整个留白机制不执行；两套机制叠加本身互不冲突，无需门控。

## 踩坑记录

### 坑 1：`type="hidden"` ≠ `widget.hidden=true`（末尾组件不可点的根因）
- **现象**：隐藏组件后节点高度错乱、末尾组件（如"影像风格"、"背景音乐"）无法点击。
- **根因**：旧实现只设 `widget.type = "hidden"`。新版可见性判断只认 `.hidden`，数百个"隐藏"组件仍参与布局与命中计算：组件被排出节点底边，Vue DOM 裁剪后无法点击。
- **解法**：隐藏时 `widget.hidden = true`，显示时还原 `false`；`type="hidden"` 与 `computeSize=()=>[0,-4]` 保留作旧前端兼容。测量/布局相关代码过滤组件时以 `.hidden` 为准。

### 坑 2：`setSize(computeSize())` 后缝隙恒为 0
- **现象**：想靠"计算高度 + 留白"直接 setSize 出留白，实际底部缝隙永远是 0。
- **根因**：`computeSize()` 返回组件自然高度，布局恰好排满该高度。
- **解法**：留白必须叠加在 computeSize 结果之上，且要防弹性组件吸收（见坑 3）。

### 坑 3：撑高节点会被文本框吸收（留白不生效的根因）
- **现象**：无论 computeSize +留白 还是 setSize 撑高，节点视觉上永远没有留白，最后一控件依旧贴底。
- **根因**：`distributeSpace` 把 `freeWidgetSpace` 全部分给不限高的弹性组件（`maxHeight: undefined`），节点撑多高文本框就长多高。
- **解法**：冻结上限（见「新版前端实现方案」第 1 步），把弹性组件锁在上一次实际分配高度，多余高度才能沉淀为真实留白。

### 坑 4：`maxHeight = minHeight` 封顶会裁剪长文本
- **现象**：直接把弹性组件 `maxHeight` 封顶为 `minHeight`，多行文本被裁掉只显示一小截。
- **根因**：实测 `minHeight` 恒为小常量（如 50）、不随内容增长。
- **解法**：首次布局不限高（拿到自然分配高度），之后以上一次实际分配的 `computedHeight` 作上限——既阻止吸收又保持文本框自然高度。

### 坑 5：setSize 后立即测量拿到旧布局 → 高度 runaway
- **现象**：节点高度每次刷新 +留白 持续爬升（实测案例 1514→1649 不停涨）。
- **根因**：布局是 Vue 异步重排。在 `setSize` 同一 tick 内测量 `widget.y` 拿到的是**上一次布局**的底边："测量→撑高→再测量"形成正反馈。
- **解法**：测量必须防抖等待布局稳定（`setTimeout 150ms` 起）；组件 `y` 未就绪时延迟重试（上限 10 次）；只向上补齐、不向下收缩，避免与用户手动 resize 打架；setSize 自身触发 onResize 时加防递归标记。

### 坑 6：扩展注册顺序不保证，onResize 守卫不可靠
- **现象**：留白扩展想在 `onResize` 里守卫留白，但显隐扩展的 handler 先跑时守卫还不存在。
- **根因**：`nodeCreated` 等钩子按扩展注册顺序执行，注册顺序不受控（文件名字母序、加载时机均不可依赖）。
- **解法**：留白扩展把调度函数挂到 `window.__确保底部留白`，显隐 handler 末尾**显式串联调用**，与注册顺序解耦。另注意：在测量入口对 `node.widgets` 全量补跑幂等冻结，同样是为覆盖晚注册扩展追加的 widget。

### 坑 7：包装 computeSize 做缩放钳制在新版前端失效
- **现象**：包装 `nodeType.prototype.computeSize`（高度+留白）期望手动缩小节点时被钳制出留白，实际用户照样能缩到贴底。
- **根因**：新版 `setSize(e) { this.size = e; this.onResize?.(this.size); }` **无钳制**；computeSize 只影响新建初始尺寸与 `expandToFitContent` 等少数路径。
- **解法**：钳制职责移交 onResize 守卫 + 防抖测量补齐（撑回底边+留白）；computeSize 包装降级为"旧前端兼容 + 初始尺寸"用途。

### 坑 8：冻结包装会解冻幽灵组件
- **现象**：`type="hidden"` + `computeSize=()=>[0,-4]` 的幽灵组件（序列化占位用）被冻结包装套上 `maxHeight` 后重新占位，节点莫名长高。
- **根因**：DOM widget 的 `computeLayoutSize` 对 `type==="hidden"` 返回全 0，冻结包装若按 `computedHeight` 重写 `maxHeight` 会把 0 上限改成正值。
- **解法**：冻结包装内对 `this.type === "hidden"` 原样返回原结果，不覆写。

### 坑 9：不要依赖 `app.vueNodesReady` 判断前端版本
- **现象**：按网上资料用 `if (!app.vueNodesReady) return;` 门控新版逻辑，结果留白机制完全不执行。
- **根因**：该属性并非所有 build 都有（ComfyUI 0.33.1 前端 bundle 实测不存在）。
- **解法**：双前端兼容写法（两套机制叠加、不门控）；确需判断时按「前端升级复核清单」实测源码特征。

### 坑 10：调试环境坑（速查表）

| 坑 | 表现 | 对策 |
|---|---|---|
| beforeunload 拦截刷新 | `navigate_page reload` 报成功但 `performance.timeOrigin` 不变，页面仍是旧代码 | 用 `performance.timeOrigin` 验证是否真刷新；清脏状态：`changeTracker.initialState = changeTracker.activeState; changeTracker.updateModified()`，或注册 capture 阶段 `stopImmediatePropagation` 拦截 |
| 模块缓存错觉 | 服务器 `cache-control: no-store` 且内容已新，但页面跑旧代码 | 先查 `navigationStart`，多数"没生效"其实是根本没刷新 |
| `app.graph.add(类名)` 报错 | `e.snapToGrid is not a function`（pysssss.SnapToGrid 禁用残留钩子） | `LiteGraph.createNode(类名)` 后再 `graph.add(node)` |
| 删除文件假成功 | 对网络盘/中文路径报成功但文件仍在 | 删除后用文件系统复核，必要时 `Remove-Item` |
| browser-use click 不稳定 | 合成点击有时不触发 pointerdown，combo 菜单打不开 | 程序化 `widget.onClick({e:{canvasX,canvasY},node,canvas})` 验证值链路 |

### 坑 11：调试坐标与命中约定
- `getWidgetOnPos(x, y)` 参数是**绝对画布坐标**（内部减 `node.pos`），传本地坐标全 null；
- 新版组件位置读 `widget.y`（旧版 `last_y`），测量代码必须两者兼容；
- 视口有 `ds.scale / ds.offset` 缩放平移，截屏对位要换算 `screen = (graph + offset) * scale`。

## 前端升级复核清单

若 ComfyUI 前端升级后本方案失效，按以下顺序复核：

1. `isWidgetVisible / getLayoutWidgets` 是否仍只认 `.hidden`；
2. `_arrangeWidgets` 是否仍把剩余空间分给 `computeLayoutSize` 组件、是否仍写 `widget.y/computedHeight`；
3. `setSize` 是否仍无钳制且触发 `onResize`；
4. vueNodesMode 下溢出是否仍不自动撑高；
5. 弹性组件的 `computeLayoutSize` 默认返回值是否仍 `maxHeight: undefined`（改为有限值则冻结上限可简化）；
6. `app.vueNodesReady` 是否（重新）可用（可用则可加版本门控，不可用维持双前端兼容写法）。

## 验证清单（浏览器实测场景）

| 场景 | 预期 |
|---|---|
| 新建目标节点 | 留白立即出现，末尾组件在节点内可点 |
| 手动拉高/拉宽节点 | 多出的高度表现为留白；宽度不被覆盖 |
| 手动缩小到内容溢出 | 节点被撑回底边+留白，末尾组件不出界 |
| 动态显隐/槽位增删反复切换 | 留白恒定，高度无 runaway（连续观察不上涨） |
| 工作流 serialize→clear→configure 往返 | 留白保持，补齐高度已随 size 持久化 |
| 旧工作流（无留白时代保存）加载 | 加载后自动补齐留白，再次保存后持久化 |
| 弹性文本组件内容变长 | 文本框保持自然高度内部滚动，不被裁剪 |

## 注意事项（通用）

1. **onResize 不可全信**：某些缩放路径（工作流加载、程序化 setSize、直接改 size 数组）不触发它，必须配 onDrawForeground 尺寸比对兜底
2. **初始布局有异步性**：`onAdded` 中 DOM 尚未完成布局，高度初始化与内容加载要用 `setTimeout`（约 100ms）延迟执行；新版前端测量更须 150ms 级防抖
3. **纯展示 DOM widget 要给空 getValue/setValue**：否则序列化时可能写入脏值或读取报错
4. **固定占位常量要与实际组件同步**：节点增删组件（如多了一个下拉框）时，高度减法的常量表要同步更新，否则内容区溢出或留白过大
5. **CSS min-width/min-height 用 !important**：`.node[data-type="节点类名"]` 选择器设最小尺寸，防止用户把节点缩到内容区崩溃
6. **内容变化也要重算高度**：加载新内容（如切换预设文件）后调用一次高度重算，保证内容区与节点尺寸一致
7. **所有原型钩子一律链式包装**：先保存原方法再 `apply`，实例级钩子（如其它扩展的 `this.onResize`）会沿原型链取到包装方法，链条不断
8. **只增不减原则**：任何自动尺寸修正都只向上/向外补齐，绝不收缩用户手动设置的尺寸
