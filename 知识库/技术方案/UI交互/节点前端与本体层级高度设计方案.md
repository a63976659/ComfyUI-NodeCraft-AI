# 节点前端与本体层级高度设计方案

## 来源
参考工具/项目：ComfyUI-prompt-formula（https://www.bilibili.com/video/BV1UBB2YhEpJ）
参考节点：图像裁剪节点（`图像裁剪节点`，实现文件 `网页资源/imagecrop.js` + `节点文件/裁剪节点.py`）
定位：节点本体（原生 widget 区）与节点前端自绘内容（画布上的图像预览/刻度尺/悬浮面板/交互框）的垂直层级划分与高度设计——自绘区从组件底边开始、高度跟随内容锁定、绘制顺序即视觉层级

## 适用场景
- 节点需要在 widget 区下方/周围自绘富 UI（图像预览、标尺、九宫格对齐面板、可拖拽裁剪框等）
- 自绘内容必须与原生 widget 互不遮挡、互不错位，widget 增删后布局自动适应
- 节点宽度允许用户自由拉伸，但高度要锁定为"内容所需高度"，防止拖出空白或压掉内容
- 自绘区内还有多层视觉元素（底图/遮罩/悬浮面板/边框/文字），需要明确的 z 序

## 核心思路
"三层垂直分层 + computeSize 动态定界 + 宽度自由/高度锁定 + 绘制顺序即 z 序"：
1. **垂直分层**：`onDrawBackground` 的自绘内容位于底层，原生 widget 由引擎绘制在上层，自绘区起点 = widget 区底边 + 顶部间距，两者天然不重叠；
2. **动态定界**：widget 区底边不硬编码，用引擎原生 `computeSize([宽度, 0])[1]` 实时获取组件真实占用高度，widget 增删/显隐后自动跟随；
3. **高度锁定**：节点高度 = max(自绘 UI 最小高度, 自绘区起点 + 内容高度 + 底部留白)，在 onResize 强制覆写 + 绘制帧校验双保险；
4. **水平四向留白**：左（尺子）/右（对称留白）/上（尺子）/下（留白）用常量定义，绘图区宽度 = 节点宽度 − 左右留白。

## 实现步骤

### 1. 布局常量：四向留白定义分层边界
```javascript
// 四个方向的固定留白，划分"组件区"与"自绘区"的边界
const paddingLeft = 30;    // 左侧：纵向刻度尺 30px
const paddingRight = 25;   // 右侧：对称留白 25px（让图片水平居中）
const paddingTop = 25;     // 顶部：横向刻度尺 25px
const paddingBottom = 15;  // 底部：收尾留白 15px（让图片垂直居中）
```

### 2. 创建时一次性扩宽（用 properties 防加载重复执行）
```javascript
async nodeCreated(node) {
    if (node.comfyClass !== "图像裁剪节点") return;

    // 给自绘区（右侧九宫格 + 左侧尺子）预留横向空间；
    // hasExpanded 标志区分"新建"与"加载工作流"，避免每次加载都叠加 +200
    if (!node.properties || !node.properties.hasExpanded) {
        node.size[0] = node.size[0] + 200;
        node.properties = node.properties || {};
        node.properties.hasExpanded = true;
    }
}
```

### 3. 动态定界：computeSize 求 widget 区底边
```javascript
// 在绘制中计算自绘区起点（每次绘制都重算，widget 变化自动适应）
node.onDrawBackground = function(ctx) {
    if (!this.imgCache) return;
    ctx.save();

    // 引擎原生 API：传 [宽度, 0] 取得组件区真实占用高度（含标题栏与全部可见 widget）
    const widgetBottomY = this.computeSize([this.size[0], 0])[1];
    const topMargin = widgetBottomY + paddingTop;   // 自绘区起点
    this.layoutTopMargin = topMargin;               // 缓存给交互逻辑复用

    // 绘图可用宽度与缩放比（自绘内容的坐标系基准）
    const drawW = this.size[0] - paddingLeft - paddingRight;
    const scale = drawW / img.width;
    this.renderScale = scale;                       // 缓存：像素↔图像坐标换算用
    const drawH = Math.floor(img.height * scale);
    // ...
};
```
这是层级高度设计的核心：**不自测、不硬编码 widget 高度**，一切以 `computeSize` 为准，组件被隐藏/增删时底边自动正确。

### 4. 高度锁定：onResize 强制 + 绘制帧校验双保险
```javascript
// 接管原生拉伸：宽度跟随用户，高度强制重算
const origOnResize = node.onResize;
node.onResize = function(size) {
    if (origOnResize) origOnResize.apply(this, arguments);
    if (this.imgCache) {
        const widgetBottomY = this.computeSize([size[0], 0])[1];
        const topMargin = widgetBottomY + paddingTop;

        const drawW = size[0] - paddingLeft - paddingRight;
        const drawH = Math.floor(this.imgCache.height * (drawW / this.imgCache.width));

        // 自绘 UI（九宫格面板）自身的最小高度需求
        const btnH = 28, gap = 4, padding = 8;
        const gridTotalH = btnH * 3 + gap * 2 + padding * 2;
        const minH = topMargin + gridTotalH + 30;

        // 高度 = max(UI 最小需求, 内容实际所需)，覆写用户拖出的高度
        size[1] = Math.max(minH, topMargin + drawH + paddingBottom);
    }
};

// 绘制帧校验：加载旧工作流/其他路径改了尺寸时兜底纠正
const minH = topMargin + gridTotalH + 30;
const neededHeight = Math.max(minH, topMargin + drawH + paddingBottom);
if (Math.round(this.size[1]) !== neededHeight) {
    this.size[1] = neededHeight;
}
```
要点：高度公式里取 `max(自绘UI最小高度, 内容高度)`，保证悬浮面板即使在矮图上也有完整容身空间。

### 5. 绘制顺序即 z 序（同层内的视觉层级）
`onDrawBackground` 中按"先底后浮"顺序绘制，后画的覆盖先画的：
```
A. 刻度尺底板（微透明黑 fillRect）+ 刻度线   ← 紧贴自绘区边缘的辅助层
B. 底图 drawImage                            ← 内容主体
C. 半透明圆角悬浮面板 + 九宫格按钮            ← 浮在图片右上（rgba(20,20,20,0.75)）
D. 裁剪框坐标计算（widget 值 × renderScale）  ← 数据层
E. 框外四块半透明遮罩（黑 0.6，精确贴边不越界） ← 压在底图上
F. 红色裁剪框 strokeRect                      ← 压在遮罩上
G. 尺寸文字                                   ← 最顶层
```
悬浮面板与图片右边缘对齐：`gridStartX = size[0] − 面板宽 − paddingRight − 5`，并把面板矩形缓存到 `this.gridRect` 供命中检测复用。

```javascript
node.onMouseDown = function(e, localPos) {
    const [mx, my] = localPos;   // localPos 已是节点本地坐标
    // 九宫格按钮：遍历 gridRect 内 3x3 网格包围盒
    // 裁剪框：落在 cropRect 内则进入拖拽，captureInput(true) 锁定输入
};
// 拖拽位移换算：屏幕像素差 / renderScale = 图像坐标差
const deltaX = (mx - this.dragState.startX) / this.renderScale;
```
绘制层（gridRect/cropRect/renderScale/layoutTopMargin）与交互层共享同一套缓存值，保证"看见的层级 = 能点到的层级"。

## ComfyUI 适配要点

1. **onDrawBackground 是正确的绘制钩子**：自绘内容画在背景层，原生 widget 由引擎绘制在其上，天然形成"组件区在上、自绘区在下"的垂直分层，无需处理遮挡
2. **computeSize([宽度, 0])[1] 是组件区底边的权威值**：它包含标题栏与全部可见 widget，且跟随 widget 显隐状态变化，永远不要手工累加组件高度
3. **宽度自由 + 高度锁定的分工**：onResize 中只覆写 `size[1]`，保留用户拖的 `size[0]`；自绘内容宽度随节点宽自适应（缩放比 = 绘图宽 / 图宽）
4. **坐标系缓存成节点属性**：renderScale、layoutTopMargin、gridRect、cropRect 在绘制时计算并挂到 node 上，交互回调直接读，避免两处重复计算产生不一致
5. **尺寸纠偏用 Math.round 比较**：浮点误差会导致"纠正→触发重绘→再纠正"的抖动，取整后比较再改

## 注意事项

1. **初始扩宽必须用 properties 标志**：nodeCreated 在新建和加载工作流时都会触发，不用 `properties.hasExpanded` 持久标记会导致每次加载宽度叠加
2. **高度校验要在绘制帧再做一次**：只靠 onResize 不够，旧工作流的保存尺寸、程序化 setSize 都绕开它，onDrawBackground 中兜底纠正才能锁死高度
3. **遮罩绘制要精确贴边**：框外遮罩按"上/下/左/右"四块分别 fillRect 并各自判断是否需要绘制，任何一块越界都会盖住裁剪框内部
4. **刻度步长要随缩放比动态升档**：`step` 按"刻度间隔 ≥ 40px"从 100 逐级升到 5000，否则小缩放比下数字互相重叠
5. **前后端数值约束要双重保障**：前端 snap16（16 倍数对齐、下限 16）与边界钳制（X ≤ 图宽 − 裁剪宽）之外，后端 `do_crop` 再做一次同样的对齐与钳制，前端被绕过时输出仍正确
6. **widget 值被程序改写后要手动触发 callback**：拖拽结束 `xW.callback(xW.value)` 通知引擎值已变化，否则依赖回调的下游逻辑（执行标记等）不触发
