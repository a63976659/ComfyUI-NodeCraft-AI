# 生命周期与缓存

## 完整执行流程

```
前端发送 Prompt
    │
    ▼
服务器解析工作流图
    │
    ▼
拓扑排序确定执行顺序
    │
    ▼
┌─────────────────────────┐
│ 对每个节点:              │
│                          │
│  1. 检查缓存             │
│     └─ fingerprint_inputs│
│        └─ 命中 → 跳过    │
│                          │
│  2. 验证输入             │
│     └─ validate_inputs   │
│        └─ 失败 → 报错    │
│                          │
│  3. 检查懒加载           │
│     └─ check_lazy_status │
│        └─ 请求缺失输入   │
│                          │
│  4. 执行节点             │
│     └─ execute           │
│        └─ 返回 NodeOutput│
│                          │
│  5. 缓存结果             │
│     └─ 以指纹为键存储    │
└─────────────────────────┘
    │
    ▼
返回结果到前端
```

## 缓存控制

### fingerprint_inputs（V3）

`fingerprint_inputs` 返回用于缓存键的值。如果返回值与上次相同，则跳过 `execute`。

```python
class CachedNode(io.ComfyNode):
    @classmethod
    def define_schema(cls):
        return io.Schema(
            node_id="CachedNode",
            display_name="Cached Demo",
            category="example",
            inputs=[
                io.Image.Input("image"),
                io.Float.Input("strength", default=1.0),
                io.Int.Input("seed", default=0),
            ],
            outputs=[
                io.Image.Output("IMAGE"),
            ],
        )

    @classmethod
    def fingerprint_inputs(cls, image, strength, seed):
        # 仅 seed 和 strength 影响缓存
        # image 不纳入指纹 → 图像变化时仍可能命中缓存
        return (strength, seed)

    @classmethod
    def execute(cls, image, strength, seed):
        # 复杂处理...
        result = image * strength
        return io.NodeOutput(result)
```

### 缓存策略选择

| 场景 | 策略 | 说明 |
|------|------|------|
| 纯变换节点 | 默认缓存 | 相同输入→相同输出 |
| 随机/种子节点 | fingerprint 包含 seed | 种子不变则命中缓存 |
| API 调用节点 | `not_idempotent=True` | 每次都执行，禁用缓存 |
| 部分输入不影响输出 | fingerprint 仅包含影响输出项 | 忽略不影响结果的输入 |

### 禁用缓存

```python
# 方式 1: Schema 标记
io.Schema(
    node_id="APINode",
    not_idempotent=True,  # 每次执行都不命中缓存
    ...
)

# 方式 2: fingerprint_inputs 返回动态值
import time

@classmethod
def fingerprint_inputs(cls, **kwargs):
    return time.time()  # 每次不同，永远不命中缓存
```

### IS_CHANGED（V1 兼容）

V1 使用 `IS_CHANGED` 方法控制缓存：

```python
# V1 方式（不推荐，仅用于理解旧代码）
@classmethod
def IS_CHANGED(cls, image, seed):
    return seed
```

V3 使用 `fingerprint_inputs` 替代。

## 输入验证 validate_inputs

`validate_inputs` 在执行前检查输入值的有效性。

### 基本用法

```python
@classmethod
def validate_inputs(cls, image, threshold, mode):
    # 返回 True 表示验证通过
    # 返回字符串表示错误消息
    if threshold < 0 or threshold > 1:
        return f"Threshold must be between 0 and 1, got {threshold}"
    if mode not in ["linear", "exponential"]:
        return f"Unknown mode: {mode}"
    return True
```

### 验证时机

1. 在 `execute` 之前调用
2. 在 `check_lazy_status` 之前调用
3. 仅在缓存未命中时调用
4. 验证失败会中止整个工作流执行

### 常见验证模式

```python
@classmethod
def validate_inputs(cls, image, dimensions, quality):
    # 尺寸验证
    h, w = image.shape[1], image.shape[2]
    if dimensions == "square" and h != w:
        return f"Expected square image, got {w}x{h}"
    
    # 数值范围验证
    if quality <= 0 or quality > 100:
        return "Quality must be between 1 and 100"
    
    # 兼容性验证
    if image.shape[-1] != 3 and quality > 80:
        return "High quality only supported for RGB images"
    
    return True
```

## 懒加载机制 check_lazy_status

详见 [输入类型详解 → 懒加载输入](../输入输出系统/输入类型详解.md#懒加载输入完整示例)

### 核心流程

```
check_lazy_status 被调用
    │
    ├─ 返回 [] → 所有懒加载输入不需要
    │
    └─ 返回 ["input_name"] → 请求指定输入
        │
        ▼
    上游节点执行，计算该输入的值
        │
        ▼
    check_lazy_status 再次被调用（可能请求更多输入）
        │
        ▼
    不再请求新输入 → 进入 execute
```

### 链式懒加载

```python
class ChainLazyNode(io.ComfyNode):
    @classmethod
    def define_schema(cls):
        return io.Schema(
            node_id="ChainLazyNode",
            inputs=[
                io.Boolean.Input("use_a", default=True),
                io.Boolean.Input("use_b", default=False),
                io.Image.Input("input_a", optional=True, lazy=True),
                io.Image.Input("input_b", optional=True, lazy=True),
            ],
            outputs=[
                io.Image.Output("IMAGE"),
            ],
        )

    @classmethod
    def check_lazy_status(cls, use_a, use_b, input_a=None, input_b=None):
        needed = []
        if use_a and input_a is None:
            needed.append("input_a")
        if use_b and input_b is None:
            needed.append("input_b")
        return needed

    @classmethod
    def execute(cls, use_a, use_b, input_a=None, input_b=None):
        parts = []
        if use_a and input_a is not None:
            parts.append(input_a)
        if use_b and input_b is not None:
            parts.append(input_b)
        if not parts:
            raise ValueError("No input selected")
        result = torch.cat(parts, dim=0)
        return io.NodeOutput(result)
```

## 输出节点标记 is_output_node

标记为输出节点的节点会触发工作流执行（即使没有下游消费者）。

```python
io.Schema(
    node_id="SaveImageNode",
    is_output_node=True,  # 标记为输出节点
    ...
)
```

### 输出节点的作用

- 确定工作流的"终点"
- 没有输出节点连接的分支不会执行
- ComfyUI 从输出节点反向追踪确定需要执行的节点

## 执行顺序

### 拓扑排序

ComfyUI 使用拓扑排序确定执行顺序：

1. 找到所有 `is_output_node=True` 的节点
2. 从输出节点反向追踪，收集所有上游节点
3. 按依赖关系拓扑排序
4. 按排序顺序依次执行

```
输出节点 (is_output_node=True)
    ↑
上游节点 A
    ↑       ↑
上游 B   上游 C    ← B 和 C 可并行
    ↑
输入节点
```

### 执行顺序规则

1. 没有依赖的节点可以并行执行
2. 有依赖的节点按拓扑序串行执行
3. 懒加载输入可能延迟上游节点的执行
4. `block_execution` 可以中止后续节点的执行
