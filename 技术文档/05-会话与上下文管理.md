# 会话与上下文管理

> 本文档描述多会话系统设计、持久化方案、上下文压缩策略和会话管理操作。  
> 最后更新时间：2026-06-20

## 多会话系统设计

### 核心概念

- 每个插件项目对应一个独立会话
- 会话列表展示在侧边栏顶部
- 新建插件时自动创建新会话
- 会话之间上下文完全隔离

### 会话数据模型

```json
{
    "session_id": "uuid-v4",
    "title": "我的图片处理节点",
    "type": "develop",
    "created_at": "2026-06-12T10:30:00Z",
    "updated_at": "2026-06-12T11:45:00Z",
    "plugin_folder": "ComfyUI-MyImageNode",
    "messages": [
        {
            "role": "user",
            "content": "帮我写一个图片翻转节点",
            "timestamp": "2026-06-12T10:30:00Z"
        },
        {
            "role": "assistant",
            "content": "好的，我来帮你创建...",
            "timestamp": "2026-06-12T10:30:05Z"
        }
    ],
    "agent_context": {
        "summary": "用户正在开发图片翻转节点，已完成基础结构...",
        "key_decisions": ["使用 V3 API", "支持水平和垂直翻转"],
        "created_files": ["__init__.py", "flip_node.py"]
    }
}
```

## 持久化方案

### 存储位置

```
ComfyUI-NodeCraft-AI/
└── 数据/
    └── 会话/
        ├── {session_id_1}.json
        ├── {session_id_2}.json
        └── ...
```

### 存储格式

- 格式：JSON 文件（每个会话一个文件）
- 编码：UTF-8
- 命名：以 session_id 命名

### 存储内容

| 字段 | 类型 | 说明 |
|------|------|------|
| session_id | string | UUID v4 唯一标识 |
| title | string | 会话标题（可自动生成或手动修改） |
| type | string | 会话所属界面类型：`develop` / `optimize` / `visualize`（旧会话无此字段时默认归入 `develop`，向后兼容） |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 最后更新时间 |
| plugin_folder | string | 关联的插件文件夹名称 |
| messages | array | 完整消息列表（用户视图） |
| agent_context | object | 智能体压缩上下文（智能体视图） |

### 读写时机

- **写入**：每次收到 AI 回复后保存
- **读取**：切换会话时加载
- **删除**：用户主动删除会话时清理文件

## 用户视图 vs 智能体视图

### 设计理念

用户和智能体看到的"历史"是不同的：

```
┌──────────────────────────────────────────────┐
│                 完整消息记录                    │
├─────────────────────┬────────────────────────┤
│     用户视图         │      智能体视图         │
├─────────────────────┼────────────────────────┤
│ • 展示所有消息        │ • 压缩后的摘要          │
│ • 可无限滚动查看      │ • 关键决策列表          │
│ • 完整的代码块        │ • 已创建文件清单        │
│ • 用于人类阅读        │ • 用于 LLM prompt      │
└─────────────────────┴────────────────────────┘
```

### 用户视图

- 完整的聊天记录，所有消息按时间排列
- 支持滚动查看历史
- 代码块完整展示
- 持久化存储在 `messages` 字段

### 智能体视图

- 压缩后的上下文，控制在 token 限制内
- 自动摘要历史对话
- 保留关键信息：用户需求、已创建文件、重要决策
- 存储在 `agent_context` 字段

## activeTab 参数传递与差异化系统提示词

### 背景

为了让同一套会话体系能在三个界面下（开发插件 / 优化插件 / 功能可视化）表现出不同的专业身份，聊天请求体增加 `activeTab` 字段。后端据此选择不同的系统提示词与检索资源。

### 请求体字段扩展

```json
POST /ai-coder/chat-stream
{
    "session_id": "…",
    "message": "…",
    "attachments": […],
    "activeTab": "develop"   // 取值 "develop" | "optimize" | "visualize"
}
```

- 前端 `交互与状态.js` / `消息渲染器.js` 在发送聊天请求时读取当前 Tab，填入 `activeTab`
- 后端 `聊天路由.py` 接收 `activeTab` 并传递给智能体 `工具路由器.py`

### 后端差异化逻辑

| activeTab | 系统提示词 | BM25 实例 | FAQ 加载 |
|-----------|----------------|------------|----------|
| `develop`   | ComfyUI 插件开发专家 | 知识库/开发插件 | ✅ |
| `optimize`  | ComfyUI 插件性能优化专家 | 知识库/优化插件 | ✅ |
| `visualize` | ComfyUI 插件功能分析专家 | 知识库/功能可视化 | ❌ |

### 上下文拼装顺序

```
[差异化系统提示词]（根据 activeTab）
  + [BM25 KB 检索 top-3]（知识库/{TAB_FOLDER_MAP[tab]}/）
  + [BM25 FAQ 检索 top-2]（数据/踩坑记录/，仅 develop / optimize）
  + [压缩后的历史消息]
  + [当前用户输入]
```

其中「BM25 KB / FAQ」部分使用不同的插入标签（「参考知识」与「历史踩坑」），以供模型辨别权威性与经验性。

## 上下文压缩策略

### 当前实现（滑动窗口）

```python
# 记忆与上下文压缩.py 中已实现
class ContextManager:
    def __init__(self):
        self.encoder = tiktoken.get_encoding("cl100k_base")
        self.max_tokens = 4000
    
    def get_compressed_history(self, messages):
        """从最新消息开始，向前填充直到达到 token 限制"""
        # 滑动窗口：保留最近的消息，丢弃较早的
        ...
```

**问题**：简单截断丢失了早期的关键信息（如用户最初的需求描述）。

### 目标实现（LLM 摘要压缩）

```
阶段 1: 检测 token 即将超限
    │
    ▼
阶段 2: 将早期消息发送给 LLM 进行摘要
    │  prompt: "请总结以下对话的关键信息..."
    ▼
阶段 3: 用摘要替换早期消息
    │  保留: 摘要 + 最近 N 条消息
    ▼
阶段 4: 构造最终 prompt
    │  [系统提示词] + [摘要] + [近期消息] + [当前输入]
    ▼
发送给 LLM
```

### 压缩保留的关键信息

| 类型 | 示例 | 重要性 |
|------|------|--------|
| 用户核心需求 | "我要写一个图片翻转节点" | 必须保留 |
| 已创建文件 | `["__init__.py", "flip.py"]` | 必须保留 |
| 重要决策 | "使用 V3 API" | 必须保留 |
| 代码细节 | 具体函数实现 | 可压缩 |
| 寒暄对话 | "谢谢"、"好的" | 可丢弃 |

### 压缩触发条件

- 当前上下文 token 数 > `max_tokens * 0.8`（预留 20% 空间）
- 每次压缩后，token 数降至 `max_tokens * 0.5`

## 会话管理操作

### 创建新会话

```
触发方式:
1. 用户点击会话栏标题区右侧「＋」按钮（整合「新建项目」入口）
   → 自动展开会话栏 → 弹出「创建项目」对话框
   → 输入插件名称（英文）
2. 后端创建插件文件夹 + 创建会话记录（标题默认为文件夹名）

结果:
- custom_nodes 下创建插件目录
- 数据/会话/ 下创建新 JSON 文件
- 前端自动切换到新会话视图

备注: 标题栏另有「✕ 取消会话」按钮，点击后恢复「节点梦工厂」欢迎页。
```

### 切换会话

```
触发方式:
1. 用户点击会话列表中的某个会话

结果:
- 加载目标会话的 messages（用户视图）
- 加载目标会话的 agent_context（智能体视图）
- 前端渲染历史消息
```

### 删除会话

```
触发方式:
1. 用户在会话上点击删除按钮
2. 弹出二级确认对话框，包含两个选项：
   a. 「仅删除会话」— 仅删除会话 JSON，保留插件文件夹代码
   b. 「删除会话和文件夹」— 同时删除会话 JSON 和 custom_nodes 下的插件目录
3. 两个选项均需再次确认（二次确认机制）

结果:
- （选项 a）删除 数据/会话/{session_id}.json，插件文件夹保留
- （选项 b）删除 数据/会话/{session_id}.json + custom_nodes/{plugin_folder}/
- 前端移除该会话，切换到其他会话或空状态
```

### 会话标题管理

| 方式 | 说明 |
|------|------|
| 自动生成 | 创建新会话时默认使用插件文件夹名作为会话标题 |
| LLM 生成 | 用 LLM 根据首轮对话生成标题（可选） |
| inline 手动修改 | 每个会话项在删除按钮旁有 ✎ 编辑按钮，点击 inline 编辑，Enter 保存 / Escape 取消，调用 `PUT /ai-coder/sessions/{id}/title` 持久化 |

#### 后端端点

```
PUT /ai-coder/sessions/{id}/title
请求体: { "title": "新标题" }
响应体: { "status": "success", "data": { "id": "...", "title": "新标题" } }
限制: 标题 500 字符上限，输入验证后保存到 数据/会话/{id}.json
```

## 三界面独立会话列表

### 设计背景

原先三个界面（开发插件/优化插件/功能可视化）共用同一套会话列表，优化面板和可视化面板的会话与开发面板的会话混杂，不易管理。

### 实现方案

**会话数据层**：会话 JSON 新增 `type` 字段，取值为 `"develop"` / `"optimize"` / `"visualize"`，标识该会话所属界面。

**后端 API 扩展**：

```
GET  /ai-coder/sessions?type=xxx   → 按 type 过滤返回对应界面的会话列表
POST /ai-coder/sessions            → 请求体支持 type 字段（默认 "develop"）
```

**向后兼容**：旧会话文件无 `type` 字段时，后端默认归入 `"develop"`，已有数据无需迁移。

**前端组件化**：新建可复用组件 `前端/会话列表面板.js`，导出 `创建会话列表面板(options)` 函数。优化面板和可视化面板各自实例化独立的侧边栏会话列表，分别传入 `type: 'optimize'` / `type: 'visualize'`；开发面板的会话列表调用加上 `type=develop` 过滤。

```
三界面各自独立侧边栏：
  开发插件  → 会话列表面板({ type: 'develop' })
  优化插件  → 会话列表面板({ type: 'optimize' })
  功能可视化 → 会话列表面板({ type: 'visualize' })
```

## 消息编辑重生成

### 功能描述

允许用户对历史消息进行编辑并重新生成回复，替代直接删除重发的操作流程。

### 交互流程

```
用户点击历史消息的「编辑」按钮
     ▼
消息进入编辑状态（文本框内联编辑）
     ▼
用户修改内容，点击「重新发送」
     ▼
前端携带 truncate_at 参数发起请求
     ▼
后端删除 truncate_at 位置之后的所有消息
     ▼
以修改后的消息为输入，重新触发 AI 生成
     ▼
新回复追加到消息流末尾
```

### 后端实现

聊天路由接收 `truncate_at` 参数（消息索引或消息 ID），在生成新回复前先截断该位置之后的历史消息，确保上下文一致性。
