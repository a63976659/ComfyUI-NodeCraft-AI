# 会话与上下文管理

> 最后更新时间：2026-06-12

## 多会话系统设计

### 核心概念

- 每个插件项目对应一个独立会话
- 会话列表展示在侧边栏顶部
- 新建插件时自动创建新会话
- 会话之间上下文完全隔离

### 会话数据模型

```json
{
    "session_id": "uuid-v4",
    "title": "我的图片处理节点",
    "created_at": "2026-06-12T10:30:00Z",
    "updated_at": "2026-06-12T11:45:00Z",
    "plugin_folder": "ComfyUI-MyImageNode",
    "messages": [
        {
            "role": "user",
            "content": "帮我写一个图片翻转节点",
            "timestamp": "2026-06-12T10:30:00Z"
        },
        {
            "role": "assistant",
            "content": "好的，我来帮你创建...",
            "timestamp": "2026-06-12T10:30:05Z"
        }
    ],
    "agent_context": {
        "summary": "用户正在开发图片翻转节点，已完成基础结构...",
        "key_decisions": ["使用 V3 API", "支持水平和垂直翻转"],
        "created_files": ["__init__.py", "flip_node.py"]
    }
}
```

## 持久化方案

### 存储位置

```
ComfyUI-NodeCraft-AI/
└── 数据/
    └── 会话/
        ├── {session_id_1}.json
        ├── {session_id_2}.json
        └── ...
```

### 存储格式

- 格式：JSON 文件（每个会话一个文件）
- 编码：UTF-8
- 命名：以 session_id 命名

### 存储内容

| 字段 | 类型 | 说明 |
|------|------|------|
| session_id | string | UUID v4 唯一标识 |
| title | string | 会话标题（可自动生成或手动修改） |
| created_at | datetime | 创建时间 |
| updated_at | datetime | 最后更新时间 |
| plugin_folder | string | 关联的插件文件夹名称 |
| messages | array | 完整消息列表（用户视图） |
| agent_context | object | 智能体压缩上下文（智能体视图） |

### 读写时机

- **写入**：每次收到 AI 回复后保存
- **读取**：切换会话时加载
- **删除**：用户主动删除会话时清理文件

## 用户视图 vs 智能体视图

### 设计理念

用户和智能体看到的"历史"是不同的：

```
┌──────────────────────────────────────────────┐
│                 完整消息记录                    │
├─────────────────────┬────────────────────────┤
│     用户视图         │      智能体视图         │
├─────────────────────┼────────────────────────┤
│ • 展示所有消息        │ • 压缩后的摘要          │
│ • 可无限滚动查看      │ • 关键决策列表          │
│ • 完整的代码块        │ • 已创建文件清单        │
│ • 用于人类阅读        │ • 用于 LLM prompt      │
└─────────────────────┴────────────────────────┘
```

### 用户视图

- 完整的聊天记录，所有消息按时间排列
- 支持滚动查看历史
- 代码块完整展示
- 持久化存储在 `messages` 字段

### 智能体视图

- 压缩后的上下文，控制在 token 限制内
- 自动摘要历史对话
- 保留关键信息：用户需求、已创建文件、重要决策
- 存储在 `agent_context` 字段

## 上下文压缩策略

### 当前实现（滑动窗口）

```python
# 记忆与上下文压缩.py 中已实现
class ContextManager:
    def __init__(self):
        self.encoder = tiktoken.get_encoding("cl100k_base")
        self.max_tokens = 4000
    
    def get_compressed_history(self, messages):
        """从最新消息开始，向前填充直到达到 token 限制"""
        # 滑动窗口：保留最近的消息，丢弃较早的
        ...
```

**问题**：简单截断丢失了早期的关键信息（如用户最初的需求描述）。

### 目标实现（LLM 摘要压缩）

```
阶段 1: 检测 token 即将超限
    │
    ▼
阶段 2: 将早期消息发送给 LLM 进行摘要
    │  prompt: "请总结以下对话的关键信息..."
    ▼
阶段 3: 用摘要替换早期消息
    │  保留: 摘要 + 最近 N 条消息
    ▼
阶段 4: 构造最终 prompt
    │  [系统提示词] + [摘要] + [近期消息] + [当前输入]
    ▼
发送给 LLM
```

### 压缩保留的关键信息

| 类型 | 示例 | 重要性 |
|------|------|--------|
| 用户核心需求 | "我要写一个图片翻转节点" | 必须保留 |
| 已创建文件 | `["__init__.py", "flip.py"]` | 必须保留 |
| 重要决策 | "使用 V3 API" | 必须保留 |
| 代码细节 | 具体函数实现 | 可压缩 |
| 寒暄对话 | "谢谢"、"好的" | 可丢弃 |

### 压缩触发条件

- 当前上下文 token 数 > `max_tokens * 0.8`（预留 20% 空间）
- 每次压缩后，token 数降至 `max_tokens * 0.5`

## 会话管理操作

### 创建新会话

```
触发方式:
1. 用户点击 "新建插件" 按钮
2. 输入插件名称（英文）
3. 后端创建文件夹 + 创建会话记录

结果:
- custom_nodes 下创建插件目录
- 数据/会话/ 下创建新 JSON 文件
- 前端切换到新会话视图
```

### 切换会话

```
触发方式:
1. 用户点击会话列表中的某个会话

结果:
- 加载目标会话的 messages（用户视图）
- 加载目标会话的 agent_context（智能体视图）
- 前端渲染历史消息
```

### 删除会话

```
触发方式:
1. 用户在会话上点击删除按钮
2. 确认对话框

结果:
- 删除 数据/会话/{session_id}.json
- 不删除插件文件夹（保留代码）
- 前端移除该会话，切换到其他会话或空状态
```

### 会话标题管理

| 方式 | 说明 |
|------|------|
| 自动生成 | 取第一条用户消息的前 20 个字符 |
| LLM 生成 | 用 LLM 根据首轮对话生成标题（可选） |
| 手动修改 | 用户双击标题编辑 |
