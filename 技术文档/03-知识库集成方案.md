# 知识库集成方案

> 本文档描述知识库的设计目标、结构规划、检索策略和维护方式。  
> 最后更新时间：2026-06-12

---

## 知识库目标

让智能体了解 ComfyUI 插件开发规范，生成符合标准、可直接运行的代码。

核心原则：
- 智能体不需要预先加载所有知识，按需检索
- 知识库内容应结构化、模块化，便于精准定位
- 生成的代码符合 ComfyUI V3 规范，重启即可测试

---

## 存储结构设计

```
知识库/
├── 总览.md                    # 所有模块的摘要索引，智能体首先读取此文件
├── 基础节点开发/
│   ├── V3节点结构与注册.md     # 来源: node-basics + 部分 packaging
│   └── 项目结构与打包.md       # 来源: node-packaging
├── 输入输出系统/
│   ├── 输入类型详解.md         # 来源: node-inputs
│   ├── 输出类型详解.md         # 来源: node-outputs
│   └── 数据类型系统.md         # 来源: node-datatypes
├── 高级开发模式/
│   ├── 动态输入与类型匹配.md   # 来源: node-advanced
│   └── 生命周期与缓存.md       # 来源: node-lifecycle
├── 前端扩展/
│   └── JS钩子与UI组件.md       # 来源: node-frontend
└── 迁移指南/
    └── V1到V3迁移.md           # 来源: node-migration
```

### 设计原则

1. **总览.md 是入口**：包含每个子文档的一句话摘要和适用场景
2. **按功能域分类**：而非按原始 repo 的模块名，更符合开发者思维
3. **每个文件独立**：包含完整的代码示例，不依赖其他文件
4. **中文标题**：便于意图匹配和智能体理解

## 智能体检索策略

### 当前实现（关键词匹配）

```python
# 工具路由器.py 中的简单实现
意图关键词 = {
    "UI": ["界面", "按钮", "sidebar"],
    "模型": ["模型", "model", "LLM"],
    "路径": ["路径", "path", "目录"],
    "节点": ["节点", "node", "input", "output"]
}
```

### 目标实现（分层检索）

```
步骤 1: 读取 总览.md
    ↓ 获取所有可用知识模块的摘要
    
步骤 2: 判断需要哪些详细文档
    ↓ 根据用户需求 + 总览摘要，决定读取哪些文件
    
步骤 3: 按需加载详细文档
    ↓ 只读取必要的文档，节省 token
    
步骤 4: 构造系统提示词
    ↓ 将知识库内容注入到 system prompt 中
```

### 检索优化方向

| 阶段 | 方式 | 优缺点 |
|------|------|--------|
| 当前 | 关键词匹配 | 简单快速，但准确度低 |
| 短期 | 规则 + 总览索引 | 通过总览摘要提升匹配精度 |
| 中期 | LLM 意图分类 | 让 LLM 判断需要哪些知识，准确但增加一次 API 调用 |
| 长期 | Embedding 向量检索 | 语义匹配，适合知识库扩大后的场景 |

## 意图识别升级方向

### 从关键词匹配到 LLM 意图分类

**方案**：在正式回答前，先用一次轻量 LLM 调用判断需要读取哪些知识文档。

```
用户消息: "帮我写一个图片处理节点，接收一个图片输入，输出处理后的图片"

意图分类 prompt:
"根据用户需求，判断需要参考以下哪些知识文档（返回文件名列表）：
- V3节点结构与注册.md
- 输入类型详解.md
- 输出类型详解.md
- 数据类型系统.md
- ..."

LLM 返回: ["V3节点结构与注册.md", "输入类型详解.md", "输出类型详解.md", "数据类型系统.md"]
```

**权衡**：增加一次 API 调用（约 100-200 token），换取更精准的知识检索。对于本地模型，延迟可接受。

## 知识库更新维护方式

### 当前实现状态

| 状态 | 项目 | 说明 |
|------|------|------|
| ✅ | 知识库结构规划完成 | 目录结构已创建，分类清晰 |
| ✅ | 检索框架已实现 | 工具路由器.py 中的 ToolRouter 类 |
| ✅ | 关键词匹配（11 个意图关键词） | 支持 UI/模型/路径/节点等意图识别 |
| ❌ | 知识库文档未填充 | 9 个待创建的知识文档 |
| ❌ | LLM 意图分类未实现 | 当前仅关键词匹配，未升级为 LLM 分类 |

### 更新触发条件

1. comfyui-custom-node-skills 上游仓库更新
2. ComfyUI 核心 API 变更（如 V3 → V4）
3. 用户反馈生成代码有误

### 维护流程

1. 监控上游仓库变更
2. 对比差异，更新对应知识文档
3. 更新 `总览.md` 中的摘要信息
4. 测试知识库检索准确度

### 版本管理

- 知识库文件纳入 Git 版本管理
- 每次更新在文件头部记录更新时间
- 重大变更记录在 `00-项目总览.md` 的更新日志中
