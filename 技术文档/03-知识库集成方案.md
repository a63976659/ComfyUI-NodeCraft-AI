# 知识库集成方案

> 本文档描述知识库的设计目标、结构规划、检索策略和维护方式。  
> 最后更新时间：2026-06-20

---

## 知识库目标

让智能体了解 ComfyUI 插件开发规范，生成符合标准、可直接运行的代码。

核心原则：
- 智能体不需要预先加载所有知识，按需检索
- 知识库内容应结构化、模块化，便于精准定位
- 生成的代码符合 ComfyUI V3 规范，重启即可测试

## 存储结构设计

### Tab 隔离后的总体结构

```
知识库/
├── develop/                     # 开发插件 Tab 专用（原全部插件开发文档）
│   ├── 总览.md
│   ├── 基础节点开发/
│   ├── 输入输出系统/
│   ├── 高级开发模式/
│   ├── 前端扩展/
│   └── 迁移指南/
├── optimize/                    # 优化插件 Tab 专用（空目录占位，后续填充）
│   └── .gitkeep
└── visualize/                   # 功能可视化 Tab 专用（空目录占位，后续填充）
    └── .gitkeep
```

> 运行时路径：AI 系统根据前端传入的 `activeTab` 参数（develop/optimize/visualize）动态加载 `知识库/{TAB_FOLDER_MAP[tab]}/`（映射为开发插件/优化插件/功能可视化）下的文档，三个 Tab 的知识互不干扰。

### develop 子目录（默认最完整）

```

├── 总览.md                    # 所有模块的摘要索引，智能体首先读取此文件（脚手架指南置顶）
├── 基础节点开发/
│   ├── 脚手架初始化与开发指南.md  # 新增：7 chunk，覆盖文件结构/__init__.py 详解/第一个节点流程/前端扩展/命名规范/requirements.txt
│   ├── V3节点结构与注册.md     # 来源: node-basics + 部分 packaging

├── 输入输出系统/
│   ├── 输入类型详解.md         # 来源: node-inputs
│   ├── 输出类型详解.md         # 来源: node-outputs
│   └── 数据类型系统.md         # 来源: node-datatypes
├── 高级开发模式/
│   ├── 动态输入与类型匹配.md   # 来源: node-advanced
│   └── 生命周期与缓存.md       # 来源: node-lifecycle
├── 前端扩展/

└── 迁移指南/

```

### 设计原则

1. **总览.md 是入口**：包含每个子文档的一句话摘要和适用场景
2. **按功能域分类**：而非按原始 repo 的模块名，更符合开发者思维
3. **每个文件独立**：包含完整的代码示例，不依赖其他文件
4. **中文标题**：便于意图匹配和智能体理解
5. **Tab 隔离**：不同 Tab 的知识领域物理隔离，避免跨领域检索噪声，同时供差异化系统提示词使用

## 知识库云端同步方向

知识库（`知识库/`）的云端同步采用 **云端 → 本地单向同步** 模式，以云端 ModelScope Dataset 为唯一权威源：

| 场景 | 行为 |
|------|------|
| 云端有、本地无 | 下载到本地 |
| 本地有、云端无 | 保留本地文件，**不上传** |
| 哈希不同 | **始终取云端版本覆盖本地** |

- 同步入口：`后端/知识库同步.py`
- `_上传本地文件()` 函数仍保留，但**不再被调用**（仅作为历史接口预留）
- 设计动机：知识库供 AI 检索，需要统一、可信、不受单个本地插件环境污染；以云端为权威源可避免多设备本地修改覆盖云端、避免误删后意外同步丢失
- 踩坑记录（`数据/踩坑记录/`）仍采用双向同步（上传 + 拉取 + 墓碑），与知识库同步策略不同

## 智能体检索策略

### 多实例 BM25（按 Tab 隔离）

```python
# 工具路由器.py：从全局单例升级为多实例字典
_bm25_indexes = {
    "develop":   BM25Index(加载路径="知识库/开发插件/"),
    "optimize":  BM25Index(加载路径="知识库/优化插件/"),
    "visualize": BM25Index(加载路径="知识库/功能可视化/"),
}
# 检索时根据请求中的 activeTab 选择对应索引
index = _bm25_indexes[active_tab]
```

- 每个 Tab 独立构建一份 BM25 索引，加载其子目录的所有 Markdown 文档
- 首次访问时懒加载（lazy），optimize / visualize 在子目录空时返回空索引不报错
- 保留原有 LRU 缓存、bigram 中英文分词机制

### FAQ 索引扩展（踩坑记录被 BM25 检索）

```
BM25 索引加载资源：
  ├─ 知识库/{TAB_FOLDER_MAP[tab]}/**/*.md   → doc_id 以文件路径为准
  └─ 数据/踩坑记录/*.json     → doc_id 以 "faq://" 前缀，仅在 develop / optimize Tab 加载
```

- 踩坑记录与知识库文档**共同参与检索**，但检索结果按前缀**分离**返回：
  - KB（知识库）：top-3
  - FAQ（踩坑记录）：top-2
- 分离返回的优点：后端可在提示词中用不同标签插入（如「参考知识」与「历史踩坑」），令模型可辨别权威性与经验性
- visualize Tab 不加载 FAQ（该场景不涉及开发踩坑）

### 检索调用样例

```python
results = router.retrieve(
    query=user_message,
    active_tab="develop",   # 决定加载哪个 BM25 实例以及是否拼接 FAQ
)
# results = {"kb": […top3…], "faq": […top2…]}
```

## Tab 差异化系统提示词

后端聊天路由根据 `activeTab` 选择不同的系统身份：

| activeTab | 系统提示词身份 | 检索资源 |
|-----------|------------------|-----------|
| `develop`   | ComfyUI 插件开发专家 | 知识库/开发插件 + FAQ |
| `optimize`  | ComfyUI 插件性能优化专家 | 知识库/优化插件 + FAQ |
| `visualize` | ComfyUI 插件功能分析专家 | 知识库/功能可视化（不加 FAQ） |

前端在聊天请求体中携带 `activeTab` 字段（取值 `"develop" | "optimize" | "visualize"`），后端聊天路由据此选择提示词与检索实例。

## 智能体检索策略（历史）

### 当前实现（关键词匹配）

```python
# 工具路由器.py 中的简单实现
意图关键词 = {
    "UI": ["界面", "按钮", "sidebar"],
    "模型": ["模型", "model", "LLM"],
    "路径": ["路径", "path", "目录"],
    "节点": ["节点", "node", "input", "output"]
}
```

### 目标实现（分层检索）

```
步骤 1: 读取 总览.md
    ↓ 获取所有可用知识模块的摘要
    
步骤 2: 判断需要哪些详细文档
    ↓ 根据用户需求 + 总览摘要，决定读取哪些文件
    
步骤 3: 按需加载详细文档
    ↓ 只读取必要的文档，节省 token
    
步骤 4: 构造系统提示词
    ↓ 将知识库内容注入到 system prompt 中
```

### 检索优化方向

| 阶段 | 方式 | 优缺点 |
|------|------|--------|
| 当前 | 关键词匹配 | 简单快速，但准确度低 |
| 短期 | 规则 + 总览索引 | 通过总览摘要提升匹配精度 |
| 中期 | LLM 意图分类 | 让 LLM 判断需要哪些知识，准确但增加一次 API 调用 |
| 长期 | Embedding 向量检索 | 语义匹配，适合知识库扩大后的场景 |

## 意图识别升级方向

### 从关键词匹配到 LLM 意图分类

**方案**：在正式回答前，先用一次轻量 LLM 调用判断需要读取哪些知识文档。

```
用户消息: "帮我写一个图片处理节点，接收一个图片输入，输出处理后的图片"

意图分类 prompt:
"根据用户需求，判断需要参考以下哪些知识文档（返回文件名列表）：
- V3节点结构与注册.md
- 输入类型详解.md
- 输出类型详解.md
- 数据类型系统.md
- ..."

LLM 返回: ["V3节点结构与注册.md", "输入类型详解.md", "输出类型详解.md", "数据类型系统.md"]
```

**权衡**：增加一次 API 调用（约 100-200 token），换取更精准的知识检索。对于本地模型，延迟可接受。
