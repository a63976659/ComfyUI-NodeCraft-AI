# 多界面架构设计

> 规划三标签页多界面体系，扩展侧边栏为「开发插件 / 优化插件 / 功能可视化」三大工作模式。  
> 最后更新时间：2026-06-22

---

## 概述

### 功能目标

将现有单一对话界面升级为三标签页多界面架构，覆盖 ComfyUI 插件开发全生命周期：

| 标签页 | 核心能力 | 面向场景 |
|--------|----------|----------|
| 开发插件 | AI 对话辅助编写新插件 | 从零创建插件 |
| 优化插件 | 选择已有插件 → AI 直接修改 | 维护/重构已有项目 |
| 功能可视化 | 三维图谱展示插件文件结构与依赖关系 | 项目分析/异常排查 |

### 设计理念

1. **渐进式复杂度** — 默认展示最简单的"开发插件"界面，高级功能按需切换
2. **组件复用** — 文件夹选择器、对话窗口作为通用组件跨标签页复用
3. **Neo-Noir 视觉统一** — 延续深色主题（`#0a0e1a` 背景、`#00ffc8` 强调色、赛博朋克光效）
4. **状态持久化** — 当前标签页、选中的插件路径均存入 localStorage

### 切换逻辑

```javascript
// 切换标签页核心逻辑（参考 ComfyUI-Ranking 实现）
function switchTab(tabId) {
    // 1. 更新按钮状态
    document.querySelectorAll('.nc-tab').forEach(btn => {
        const isActive = btn.dataset.tab === tabId;
        btn.classList.toggle('active', isActive);
    });
    // 2. 切换面板显示
    document.querySelectorAll('.nc-panel').forEach(panel => {
        panel.style.display = panel.id === `panel-${tabId}` ? 'flex' : 'none';
    });
    // 3. 持久化
    localStorage.setItem('NodeCraftAI_activeTab', tabId);
}
```

### 状态持久化

| 存储键 | 值类型 | 说明 |
|--------|--------|------|
| `NodeCraftAI_activeTab` | string | 当前标签页 ID（develop/optimize/visualize） |
| `NodeCraftAI_selectedPlugin` | string | 优化/可视化模式下选中的插件路径 |
| `NodeCraftAI_visualizeCamera` | JSON | 3D 视图相机位置（可选） |

### 插件文件夹与会话互斥选择机制

优化/可视化面板中，插件列表选择和会话关联的文件夹两个来源互斥，避免智能体无法确定操作目标。

| 状态 | 值 | 说明 |
|------|-----|------|
| `最后文件夹来源` | `'plugin'` | 最后一次操作是选择插件列表 |
| `最后文件夹来源` | `'session'` | 最后一次操作是切换到带文件夹的会话 |
| `最后文件夹来源` | `null` | 当前无文件夹选择 |

**互斥规则：**
- 选择插件列表 → `最后文件夹来源 = 'plugin'`，清除会话选中
- 切换到带 `plugin_folder` 的会话 → `最后文件夹来源 = 'session'`，清除插件列表选中
- 状态栏显示最终生效文件夹，无选择时显示“无”

### 智能体能力说明

在"优化插件"模式下，智能体具备以下额外能力：

| 能力 | 说明 | 实现方式 |
|------|------|----------|
| 读取插件文件 | 浏览选中插件的目录树和文件内容 | 后端 API 扫描 |
| 修改插件文件 | 直接写入/修改目标插件中的代码文件 | 文件写入 API |
| 结构分析 | 识别 `__init__.py`、节点类、前端 JS 等 | 静态分析 |
| 依赖检查 | 检查 requirements.txt 和导入语句 | AST 解析 |
| 重构建议 | 提供代码优化和 V3 迁移建议 | LLM + 知识库 |

### 工作流

```
用户选择插件 → 后端扫描目录结构 → 智能体加载文件树上下文
     ▼
用户描述需求 → 智能体分析现有代码 → 生成修改方案
     ▼
用户确认 → 智能体执行文件修改 → 反馈修改结果
```

### 双模式升级（已实现）

选择文件夹后不再自动分析，改为从历史文件加载，用户手动选择模式后点击「开始分析」：

| 衰减系数 | 0.92 | 动画衰减速度 |
| 最小距离 | 40 | 节点最小间距（像素） |
| 重力中心 | (0,0,0) | 向中心的微弱引力 |

## 会话列表面板公共组件

### 设计目标

`前端/会话列表面板.js` 统一封装三个面板的会话列表 UI，通过配置参数实现差异化行为。

### 创建组件的配置选项

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `type` | string | `'develop'` | 会话类型（develop / optimize / visualize） |
| `onPackageClick` | function | null | 点击打包按钮的回调 |
| `onCancelClick` | function | null | 点击取消按钮的回调 |
| `onToggleCollapse` | function | null | 折叠状态切换回调 |
| `defaultCollapsed` | boolean | false | 默认是否折叠 |
| `showSearch` | boolean | true | 是否显示搜索会话框（优化/可视化为 false） |
| `showCancelButton` | boolean | true | 是否显示标题栏取消按钮（×） |
| `showCurrentSessionLabel` | boolean | true | 折叠时是否显示当前会话标题 |
| `onNewClick` | function | null | 点击 + 按钮的回调 |
| `useGlobalState` | boolean | false | 是否共享全局会话状态 |

### 返回的控制对象

```javascript
const 会话列表控制 = 创建会话列表面板(container, {
    type: 'optimize',
    showSearch: false,
    showCancelButton: true
});

// 返回对象属性：
会话列表控制.refresh()               // 手动刷新会话列表
会话列表控制.getCurrentSessionId()    // 获取当前选中会话 ID
会话列表控制.destroy()                // 销毁组件
会话列表控制.getCurrentSession()       // 获取当前会话对象
会话列表控制.isCollapsed()             // 是否当前折叠
会话列表控制.clearSelection()          // 清除会话选中
```

### + 按钮布局

`+` 按钮始终靠右对齐，通过 flex spacer（`flex:1` 的占位元素）实现，不受标题文字长度影响。

## 登录面板独立化设计

### 设计背景

原先登录入口耦合在设置面板的“账号”Tab 中，用户需要先打开设置面板才能登录，交互层级过深。同时默认入口为品牌介绍页，未登录用户需额外操作才能进入登录流程。

### 核心调整

| 调整项 | 变更前 | 变更后 |
|--------|--------|--------|
| 登录入口位置 | 设置面板“账号”Tab 内 | 右上角✦星星按钮独立全屏覆盖面板 |
| 设置面板 Tab 结构 | 模型设置 / GitHub / 账号 | 模型设置 / GitHub / 监控 / 云端同步（移除账号Tab） |
| 默认入口界面 | 品牌介绍页 | 登录界面 |
| 登录后操作 | 无明确引导 | “进入 →”按钮进入主界面 |
| 关闭按钮 | 有右上角全局关闭 | 移除（双入口均无关闭按钮） |

### 全屏覆盖层架构

星星按钮（✦）点击后弹出独立的全屏覆盖登录面板，采用与设置面板一致的覆盖层结构：

```
┌──────────────────────────────────────────┐
│              nca-overlay（全屏遮罩）        │
│  ┌────────────────────────────────────┐  │
│  │         nca-panel（面板容器）        │  │
│  │  ┌──────────────────────────────┐  │  │
│  │  │    nca-panel-header（头部）    │  │  │
│  │  └──────────────────────────────┘  │  │
│  │  ┌──────────────────────────────┐  │  │
│  │  │  nca-panel-body（内容区）       │  │  │
│  │  │  ┌────────────────────────┐  │  │  │
│  │  │  │ .nca-login-center-wrap  │  │  │  │
│  │  │  │ (max-width: 480px,     │  │  │  │
│  │  │  │  margin: 0 auto)       │  │  │  │
│  │  │  │  ┌──────────────────┐  │  │  │  │
│  │  │  │  │  创建登录面板()    │  │  │  │  │
│  │  │  │  └──────────────────┘  │  │  │  │

│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

- 登录内容通过 `.nca-login-center-wrap`（`max-width: 480px`、`margin: 0 auto`）在全屏中居中展示
- 内部调用 `创建登录面板()` 函数渲染登录表单
- `显示登录弹窗()` 函数定义在 `前端/会话视图管理器.js` 中

### 双入口一致性

项目存在两个登录入口，二者 UI 与交互逻辑完全统一：

| 入口 | 触发方式 | UI 一致性 |
|------|----------|-----------|
| 默认入口 | 应用启动时未登录 → 直接展示登录界面 | 与星星按钮入口完全一致 |
| 星星按钮入口 | 点击右上角✦按钮 → 弹出全屏覆盖层 | 与默认入口完全一致 |

两个入口均**不显示关闭按钮**，登录成功后统一显示“**进入 →**”按钮。

### 登录流程

```
应用启动
    ▼
检查登录状态
    ├── 已登录 → 进入主界面（三标签页）
    └── 未登录 → 显示登录界面（默认入口）
                      ▼
              用户输入凭证并提交
                      ▼
              登录成功 → 显示“进入 →”按钮
                      ▼
              点击“进入 →” → 进入主界面

（已登录状态下点击✦按钮 → 弹出全屏覆盖登录面板）
```

退出登录按钮保持**小型化设计**，不占据显著视觉权重。

## 三维可视化引擎

### 技术选型

| 方案 | 库 | 优势 | 劣势 | 推荐 |
|------|-----|------|------|------|
| 方案 A | Three.js + 3d-force-graph | 真 3D、交互流畅、GPU 加速 | 体积较大（~500KB） | ⭐ 推荐 |
| 方案 B | D3-force-3d + Three.js | 力导向算法成熟 | 需自行处理渲染 | 备选 |
| 方案 C | Sigma.js（2D） | 轻量、2D 性能好 | 无 3D 效果 | ❌ 不推荐 |

**最终选型**：`3d-force-graph`（基于 Three.js 封装）

- NPM：`3d-force-graph`
- 大小：压缩后 ~180KB（含 Three.js 依赖）
- 特性：内置力导向布局、节点/连线渲染、相机控制、事件系统
- 兼容性：WebGL 2.0，所有现代浏览器支持

### 数据模型

```javascript
// 可视化数据结构定义
const graphData = {
    nodes: [
        {
            id: "文件路径（相对于插件根目录）",
            name: "文件名",
            type: "python | javascript | config | directory | entry",
            size: 1024,           // 文件大小（字节）
            status: "normal | error | warning",
            group: "目录名"       // 用于分组着色
        }
    ],
    links: [
        {
            source: "源文件路径",
            target: "目标文件路径",
            type: "import | weak | external",
            status: "normal | error",
            label: "依赖描述（可选）"
        }
    ]
};
```

### 渲染配置

```javascript
// 3d-force-graph 初始化配置
const graph = ForceGraph3D()(containerElement)
    .graphData(graphData)
    .nodeColor(node => nodeColorMap[node.type])
    .nodeVal(node => node.type === 'directory' ? 8 : 3)
    .linkColor(link => linkColorMap[link.status])
    .linkWidth(link => link.status === 'error' ? 2 : 1)
    .linkOpacity(0.6)
    .backgroundColor('#0a0e1a')
    .d3Force('charge', d3.forceManyBody().strength(-120))
    .d3Force('link', d3.forceLink().distance(60))
    .onNodeClick(handleNodeClick)
    .onNodeHover(handleNodeHover);
```

### 数据生成流程

```
用户选择插件目录
      ▼
后端 API: POST /ai-coder/analyze-plugin
      ▼
┌──────────────────────────────────┐
│  1. 扫描目录树（os.walk）         │
│  2. 解析 Python 文件 import 语句  │
│  3. 解析 JS 文件 import/require   │
│  4. 检测循环依赖（DFS）           │
│  5. 验证导入目标是否存在          │
│  6. 标记异常连线（红色）          │
└──────────────────────────────────┘
      ▼
返回 graphData JSON → 前端渲染
```
