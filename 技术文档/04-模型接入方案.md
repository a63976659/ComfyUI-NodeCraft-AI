## 工具调用循环上限（API 模型）

### 当前配置

`智能体/API模型客户端.py` 中非流式和流式均配置为 15 轮：

```python
最大工具循环次数 = 15

# 非流式（第 156 行）和流式（第 348 行）均使用同一变量，提示信息动态引用：
f"[提示] 工具调用循环达到上限（{最大工具循环次数} 轮）"
```

### 调整原因

5 轮不够支持复杂任务：模型在探索阶段（读文件树、读多个文件）就消耗大量轮次，剩余轮次不足以完成写入。提升至 15 轮可支持先探索再修改的复杂多文件场景。

## 本地模型工具调用适配层

### 问题背景

API 模型通过 OpenAI Function Calling 原生支持工具调用，但本地 transformers 模型在推理时仅输出纯文本，无法直接触发文件操作工具。为了让本地模型也能完成"读取插件文件 → 分析 → 写入代码"的闭环，需要一套文本级适配层。

### 解决方案

采用 `<tool_call>` XML 标记约定，让本地模型在纯文本回复中嵌入结构化工具调用：

```text
<tool_call>{"name": "read_plugin_file", "arguments": {"file_path": "__init__.py"}}</tool_call>
```

后端解析模型输出中的标记，提取工具名与参数，执行对应操作后将结果以 `[工具结果: xxx]` 格式反馈给模型，继续下一轮生成。

### 核心组件

| 组件 | 文件 | 职责 |
|------|------|------|
| 本地模型工具解析器 | `智能体/本地模型工具解析器.py` | 解析 `<tool_call>` 标记；提取/分离/清理工具调用；提供 JSON 容错修复 |
| 增强本地模型客户端 | `智能体/本地模型客户端.py` | 新增 `generate_response_with_tools` 与 `流式对话_with_tools`；管理最多 15 轮工具调用循环 |
| 路由适配 | `后端/聊天路由.py` | 非流式与流式分支均支持本地模型工具调用 |
| GraphQL 流式适配 | `后端/GraphQL模式/解析器/聊天逻辑.py` | 流式订阅与本地模型工具调用链路对接 |
| 前端过滤 | `前端/交互与状态.js` | 新增 `_过滤工具标记` 函数，兜底过滤残留 `<tool_call>` 标记，保留进度提示 |

### 工作流程

```
用户输入
  ↓
system prompt 注入可用工具说明
  ↓
本地模型生成回复
  ↓
检测 <tool_call> 标记
  ├─ 无标记 → 直接返回给用户
  └─ 有标记 → 解析工具名与参数
            ↓
        执行文件操作工具
            ↓
        结果以 [工具结果: xxx] 追加到上下文
            ↓
        模型继续生成（循环）
            ↓
        达到 15 轮上限或不再输出标记 → 返回最终回复
```

### 支持的工具列表

| 工具名 | 参数 | 说明 |
|--------|------|------|
| `read_plugin_file` | `file_path` | 读取指定插件文件内容 |
| `write_plugin_file` | `file_path`, `content` | 写入完整文件内容（覆盖） |
| `list_plugin_files` | 无 | 列出当前插件项目的文件结构 |

### 容错机制

解析失败时启用三层修复策略：

1. **正则提取**：使用 `<tool_call>` 正则匹配原始文本中的标记块；
2. **JSON 局部修复**：截断标记后多余内容、补全缺失的 `}` / `]`；
3. **模型自省修复**：将错误信息回传给模型，请求其重新输出合规的 `<tool_call>`。

### 与 API 模型工具调用的差异

| 维度 | API 模型（Function Calling） | 本地模型（XML 标记适配） |
|------|------------------------------|--------------------------|
| 调用格式 | JSON Schema / `tool_calls` 字段 | `<tool_call>{...}</tool_call>` 纯文本标记 |
| 解析位置 | 客户端 SDK 解析 | 后端自定义解析器 |
| 循环上限 | 15 轮 | 15 轮 |
| 前端处理 | 隐藏 `tool_calls` | 过滤 `<tool_call>` 标记，保留 `[正在执行: ...]` 进度提示 |

## 本地模型推理实现细节（LocalModelClient）

### 核心实现

```python
# 模型客户端.py 中的 LocalModelClient
from transformers import AutoModelForCausalLM, AutoTokenizer
import asyncio

class LocalModelClient:
    def __init__(self):
        self.model = None
        self.tokenizer = None
        self.current_model_path = None

    def load_model(self, model_path):
        """加载本地模型，自动 GPU 分配"""
        # 卸载旧模型释放显存
        if self.model is not None:
            del self.model
            del self.tokenizer
            torch.cuda.empty_cache()
        
        self.tokenizer = AutoTokenizer.from_pretrained(model_path)
        self.model = AutoModelForCausalLM.from_pretrained(
            model_path,
            device_map="auto",      # 自动 GPU 分配
            torch_dtype="auto"       # 自动精度选择
        )
        self.current_model_path = model_path

    async def generate(self, messages, **kwargs):
        """异步推理，避免阻塞事件循环"""
        loop = asyncio.get_event_loop()
        result = await loop.run_in_executor(
            None,
            self._sync_generate,
            messages,
            kwargs
        )
        return result

    def _sync_generate(self, messages, kwargs):
        """同步推理实现"""
        inputs = self.tokenizer.apply_chat_template(
            messages, return_tensors="pt"
        ).to(self.model.device)
        outputs = self.model.generate(inputs, **kwargs)
        return self.tokenizer.decode(outputs[0], skip_special_tokens=True)
```

### 关键技术点

| 技术点 | 实现方式 | 说明 |
|--------|----------|------|
| 模型加载 | `AutoModelForCausalLM.from_pretrained(path, device_map="auto")` | 自动分配 GPU/CPU |
| 异步推理 | `asyncio.run_in_executor` | 避免阻塞 aiohttp 事件循环 |
| 模型切换 | 卸载旧模型 + `torch.cuda.empty_cache()` | 释放显存后加载新模型 |
| 精度管理 | `torch_dtype="auto"` | 根据模型配置自动选择 |

## 通道A - 本地模型

### 模型存储路径

| 类型 | 路径 | 说明 |
|------|------|------|
| 默认路径 | `ComfyUI\models\LLM` | 根据 ComfyUI 安装位置自动定位 |
| 自定义路径 | 用户设置 | 用户可在设置面板中指定任意路径 |
| 恢复默认 | 一键操作 | 清除自定义配置，回到默认路径 |

### 路径获取逻辑

```python
# 系统环境映射.py 中已实现基础版
def get_default_llm_path():
    """获取默认 LLM 模型路径"""
    models_dir = folder_paths.models_dir  # ComfyUI models 目录
    return os.path.join(models_dir, "LLM")
```

### 支持的模型格式

- **GGUF**：主要支持格式，兼容 llama.cpp 生态
- 量化级别：Q4_K_M、Q5_K_M、Q8_0 等

### 本地推理引擎选型

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| llama-cpp-python | 纯 Python 绑定，易集成 | 需编译，依赖 C++ 环境 | 深度集成 |
| Ollama 本地 API | 独立服务，API 兼容 | 需额外安装 Ollama | 用户已有 Ollama |
| llama.cpp server | 轻量级 HTTP 服务 | 需手动启动 | 灵活部署 |

**推荐方案**：优先支持 llama-cpp-python（深度集成），同时兼容 Ollama API（作为本地 API 模式）。

## 通道B - API 模型

### 当前实现

```python
# 模型客户端.py 中已实现
class AICoderClient:
    def __init__(self):
        self.base_url = "http://localhost:11434/v1"  # 默认 Ollama
        self.model = "qwen2.5-coder-32b-instruct"
        self.temperature = 0.2
```

### 目标实现

支持配置项：
- `base_url`：API 端点地址
- `model_name`：模型名称
- `api_key`：API 密钥（加密存储）
- `temperature`：生成温度
- `max_tokens`：最大输出 token 数

### 支持的 API 提供商

| 提供商 | base_url 示例 | 典型模型 |
|--------|---------------|----------|
| OpenAI | `https://api.openai.com/v1` | gpt-4o, gpt-4o-mini |
| DeepSeek | `https://api.deepseek.com/v1` | deepseek-coder, deepseek-chat |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | qwen-coder-plus |
| Ollama (本地) | `http://localhost:11434/v1` | 任意本地模型 |
| 自定义 | 用户填写 | 任意 OpenAI 兼容模型 |

### API Key 安全存储

```
存储位置: ComfyUI-NodeCraft-AI/数据/config.json（加密）
加密方式: 本地密钥 + AES 对称加密（或使用 keyring 库）
读取流程: 启动时解密加载到内存，不在日志中输出
```
